# Scene rewriting and lexical rejection audit

This development audit separates actual model generations from authored candidate
checks. It changes no production prompt, scene mapping or validation policy.
The user's intended behavior is scene-appropriate organization, paraphrase and
structure while preserving meaning, requirements, facts and uncertainty.

## Actual installed-worker generations

[`inputs.json`](inputs.json) contains four authored cases. `requestedScene` is
the product scene; `scene` is its effective model layout, selected according to
the inspected `domain.ModelScene` mapping. This is not an OS scene-classification
test. The installed worker produced these observed results:

| Case | Effective layout | Generation | Verdict |
| --- | --- | --- | --- |
| Work message without explicit enumeration | chat | Original paragraph unchanged | accepted |
| Work plan with three explicit items | list | Three numbered lines | accepted |
| Coding request with two explicit items | list | Spoken ordinals retained inline | accepted |
| Leave-request email | email | Greeting and body separated | accepted |

Raw results, model/runtime provenance and hashes are in
[`benchmarks/runs/scene-rewrite-audit-v1`](../../runs/scene-rewrite-audit-v1).
Inference uses the verified installed worker and the same pinned assets as the
[rejection diagnostic](../rewrite-rejection-v1/README.md), greedy decoding and
four threads. No microphone, screen capture or target insertion was performed.

The actual shipped model templates teach only chat, email and list. Work and
coding-prompt scenes map to list when `domain.Enumerated` detects a declared
ordinal pair; otherwise they map to chat. A work scene therefore does not
currently ask for semantic grouping or headings from an unenumerated paragraph.

## Authored candidate checks

[`validator-probes.json`](validator-probes.json) retains five authored
source/candidate pairs and the production validator's actual verdicts. These
candidates were written for diagnosis, not generated by a model or independently
reviewed as semantic gold:

| Candidate transformation | Verdict |
| --- | --- |
| Keep wording, replace spoken ordinals with numbered lines | accepted |
| Rephrase a slow-interface request as a concise diagnostic request | unsupported_content |
| Organize login progress, testing dependency and release restriction under headings | unsupported_content |
| Rewrite `five minute TTL` as `5-minute TTL` in numbered requirements | new_number |
| Rephrase `今天先别发。` as `今天暂缓发布。` | negation_dropped |

`ValidateRewrite` receives no scene or rewrite-mode policy. Its shared checks
ignore punctuation and list labels, but constrain lexical expansion, novelty,
coverage, numeric spelling and recognized negation/uncertainty. Coverage is a
case-insensitive character multiset, not sentence overlap or semantic fidelity.
Novelty compares CJK characters and Latin words against source/context. These
proxies can reject a meaning-preserving paraphrase and can also accept a meaning
change that reuses the same words.

Historical scene runs show both real generation errors and false rejections:
the analytics example adds an optimization task, whereas the `five` to `5`
conversion alone triggers `new_number`. They should not be conflated.

## Chatterfly comparison

The [official site](https://chatterfly.tencent.com/) describes scene/intent
recognition and Skills for deeper polishing. The retained
[client investigation](../../../docs/research/chatterfly.md) identifies work-message
and coding-prompt scenes, stable ASR plus context/configuration sent to
post-processing, and distinct original/enhanced text. The
[result-policy investigation](../../../docs/research/competitor-disfluency.md#chatterfly-stable-asr-text-enters-the-post-processor)
found no lexical-retention or length-ratio check in the bounded client success
path. This does not establish that the service has no validation. Its exact
server prompts, models and semantic policy remain unavailable; no live Chatterfly
speech session was run in this audit.

## Reproduction

Build the validator as described in the rejection diagnostic, then run its
parameterized runner with this audit's `inputs.json` and a fresh output directory:

```sh
python3 benchmarks/reproduction/rewrite-rejection-v1/run.py \
  --inputs benchmarks/reproduction/scene-rewrite-audit-v1/inputs.json \
  --out .workspace/scene-rewrite-repeat
```

For each authored candidate, send `operation=validate`, `mode=product`, `text`
and `candidate` to `.workspace/rewrite-rejection-v1/validate`; compare its
`verdict` to the retained result. These small development probes establish
mechanisms, not quality rates or a replacement semantic validator.
