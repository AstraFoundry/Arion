# Windows native ASR diagnostics

These are actual Windows amd64 observations from the production Go ASR adapter and the staged speech.cpp 0.8.11 workers. The Qwen3-ASR 1.7B Q8_0 file matched the catalog SHA-256 `5f219b78a1d9c3b9e97da27708b36f8a0bc1bfc1650b541c0a6dbaf87c9a62d0`. Runtime provenance is pinned in [`scripts/asr-runtime.json`](../../../scripts/asr-runtime.json); each observation file records its actual executable digest, processor identifier, logical CPU count, threads and Go version. The Vulkan loader was present. The two backends ran sequentially on an AMD Ryzen 7 7840U with Radeon 780M integrated graphics and approximately 30.8 GB OS-visible physical memory. `observations/*-devices.json` preserve actual worker device enumeration collected after inference; their free-memory readings are not inference-time samples. Windows reports build 26200.9445, display version 25H2.

Each backend completed six offline development utterances (two AISHELL Mandarin, two LibriSpeech English, two synthetic mixed-language fixtures), cancellation with a 100 ms deadline, successful reuse of the resident worker after cancellation, and three realtime streaming sessions delivered in 20 ms frames. Streaming observations retain native partials separately from final text, identity, revision, first partial, stop-to-result and cumulative inference time. A cancelled request can take longer than its deadline while the production adapter drains the worker's cancellation acknowledgement.

This is runtime and transport acceptance on one host, not a held-out quality benchmark, minimum-device claim or microphone test. Every actual decoded output is retained, including errors in words and tail content. Both mixed-language TTS inputs were recognized incorrectly: `standup` became `温度`; the `PR / merge / main / CI` input also lost technical meaning. One Mandarin output omits the final `中`, another writes `金九` for reference `今久`; an English output writes `quite` for `wide`. CPU and Vulkan mixed outputs differ. Successful worker execution does not satisfy SPH-A03 or authorize a quality claim.

Observed short-utterance CPU offline calls took approximately 4.5–6.0 seconds; warm Vulkan calls after the first took approximately 0.48–0.96 seconds. These individual diagnostic timings are affected by host load and do not establish p95/p99 or release budgets. The first Vulkan call took approximately 3.13 seconds. The CPU cancellation acknowledgement took approximately 4.49 seconds; the next request still succeeded.

`observations/cpu.jsonl` and `observations/vulkan.jsonl` preserve the original run bytes. `archive.json` binds those bytes and the source snapshot. `probe.go` is the same diagnostic program with formatting normalized after execution; the original compiled diagnostic executable remains in the private workspace. The exact production adapter code is identified by the source revision in the archive; no production ASR code changed during these runs. Weights, native executables and personal paths are not redistributed. Audio is reused from the already archived [`asr-v1` corpus](../../corpora/asr-v1/corpus.json), including its licenses, source hashes and dev split. References are held only in the diagnostic evaluator and never sent in recognition requests.

From the repository root, reproduce with Go 1.27.1, the staged native worker and the catalog model file:

```powershell
go run ./benchmarks/reproduction/windows-native-asr-v1/probe.go -root C:\project\Arion -model C:\path\Qwen3-ASR-1.7B-Q8_0.gguf -worker C:\project\Arion\apps\desktop\resources\windows-amd64\asr\speech-vulkan.exe -out C:\path\new-evidence-directory
```

Use `speech.exe` in a separate new output directory for the CPU route. Both are real inference; the explicit worker path selects a diagnostic backend. The packaged product chooses Vulkan when the system loader is present and surfaces selected-runtime failures.

The actual installer was installed into an isolated workspace directory, then `TestWindowsPackagedSpeech` ran against that installed `Arion.exe` and its selected bundled Vulkan worker. The five-case suite passed in 27.30 seconds. `observations/installed/trace.jsonl` retains the original native observations and editor contents; its original SHA-256 sidecar is preserved alongside the test log and application log. The executable SHA-256 is `c822189b8acec48b403dc9f655cca6f09a029257f021a2a54065dee1068089af`. The test selected the installed bundled worker through the product selection policy and forced no external worker override.

The fixed LibriSpeech development utterance reached the real owned Win32 editor as `Anyhow, we want to help. Got a job for us?`; duplicate confirmation left one insertion attempt and exactly 42 native character messages. The production SendInput result correctly remains `unknown` without a host acknowledgement, even though the owned editor independently reports the inserted text. The cancellation and focus-change cases first observed that real recognition reached the delayed final-result gate. Cancellation inserted nothing; changed focus produced `not_applied / TARGET_CHANGED` and neither editor changed. The committed silence fixture produced `NO_SPEECH` with zero insertion attempts. The password field produced `SECURE_FIELD_BLOCKED` before capture opened. The owned installed application exited normally and both owned editors closed; the temporary profile was removed. The installed test used the verified catalog model from an isolated offline store.

`sources/` preserves the exact speech-test, owned-editor fixture and control-harness sources used by that packaged run. `attempts/argument-parsing.log` retains an initial PowerShell native-argument quoting failure; no packaged application or inference started in that attempt. The corrected argument-array launch completed the suite. For the reproduction command and opt-in environment variables, see [`docs/quality/e2e.md`](../../../docs/quality/e2e.md).

These package scenarios establish recognition and insertion mechanics on owned native editors. They do not establish browser/Electron/Office compatibility, elevated target delivery, microphone behavior, network isolation, update-feed authenticity or broad speech accuracy. Actual microphone and installer/update checks are separate evidence in the Windows validation report.
