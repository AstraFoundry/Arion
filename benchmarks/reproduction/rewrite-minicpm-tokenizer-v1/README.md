# MiniCPM native versus official input tokens

All202 complete native prompts from the actual [MiniCPM comparison](../rewrite-selector-minicpm-v1/README.md) have exactly identical token ID sequences between native b11734 `/tokenize` (special markers parsed, no extra special tokens) and the official pinned upstream `tokenizer.json` loaded through isolated PyPI tokenizers0.22.1. No additional model generation. This rules out token-ID divergence for these inputs; it is not a logits/weight-conversion, upstream chat-serializer, semantic or release equivalence proof.

`original-run.py.txt` retains the actual executing script. `tokenizer.json` is original public Apache2 tokenizer data, not model weights; `receipt.json` pins upstream revision/URL/bytes/SHA. Run `python3 benchmarks/reproduction/rewrite-minicpm-tokenizer-v1/report.py` to verify source/request bindings and all202 exact sequences offline without native/tokenizer dependencies. `benchmarks/runs/rewrite-minicpm-tokenizer-v1/` retains raw template requests/prompts/native IDs/upstream IDs, plan/status/server metadata/logs and failed attempts. The first script failed argument grouping; the second hit the preinstalled0.11.0 tokenizer's unsupported model JSON format. Both occurred before native requests. The corrected run used a private0.22.1 install and left system dependencies unchanged.

For fresh execution, provision the same private model/runtime and isolated tokenizer library, copy `original-run.py.txt` as `run.py` and the pinned tokenizer into a new private directory, then run it from the repository root with that isolated dependency directory on Python's import path. It exclusively creates native output; never overwrite original run directories. All current source rows and weight/runtime hashes are verified first. Dependencies, weights and runtime binaries remain private.
