# Qwen3-ASR 1.7B and system accessibility diagnostic

This study tests two separate changes: X-ASR streaming with a Qwen3-ASR 1.7B INT8 acoustic finalizer, and visible system-accessibility window text instead of product screenshots/OCR. The ASR arms hold X-ASR 160 ms streaming, four CPU threads, 20 ms realtime replay, 800 ms endpoint silence, memory/ranker/correction off and one seed fixed. Full development audio comes from the existing [ASR corpus](../../corpora/asr-v1/corpus.json). This is exposed development evidence, not a new held-out claim.

`window-probe.m` opens an owned AppKit editor and renders the exact 12 prior [entity context fixtures](../../corpora/entity-ocr-v1/corpus.json). Three paired Accessibility/Vision reads per case measure real window collection. A password and a hidden text canary check exclusion. Both source texts then feed the same installed production Qwen3.5-2B worker, with final rewriting only and the fixture's scene. No references enter the rewrite request. The 24 proposals require explicit assistant inspection. This does not establish third-party application coverage, microphone delivery, native preview latency, Windows runtime acceptance or independently reviewed semantic quality.

The candidate ASR artifact uses six individual revision-pinned ModelScope files linked by the [sherpa-onnx export documentation](https://k2-fsa.github.io/sherpa/onnx/qwen3-asr/export.html). The native production adapter loads all graphs with sherpa-onnx 1.13.8 CPU. Weights stay in the private cache; upstream metadata, digests, native dependency identities, inputs, source snapshots, raw outputs and failures are retained in the archive. Original floating-point checkpoint parity is unverified.

After explicit provisioning, run the native driver through the existing harness:

```sh
pnpm bench:run --config benchmarks/configs/qwen17-accessibility-asr.json --corpus benchmarks/corpora/asr-v1/corpus.json --driver /absolute/verified-driver.json --out /absolute/new-run
pnpm bench:report --results /absolute/new-run
```

The driver must pin its executable, all model/tokenizer files, catalog and actual native libraries. `arion-models ensure -artifact qwen3-asr-1.7b-int8 -root <store>` provisions the candidate; `-offline` verifies without network. Existing output paths are never overwritten. Native AppKit compilation links `window-probe.m` and production `accessibility.m`, `context.m`, `native.m` with Cocoa, ApplicationServices, AVFoundation, Carbon, Security, ScreenCaptureKit, Vision and ImageIO. Capture and OCR remain in this comparison tool for the historical control; product `Targets.ReadContext` uses Accessibility only.

The [window run](../../runs/qwen17-accessibility-v1/window/summary.json) retains the 36 real paired reads and 24 reviewed rewrites. A second native probe verifies visible-range exclusion, stale-target rejection and node-limit rejection without partial text. The original collection source is retained under `window-source`; editable-field reads were subsequently tightened to visible ranges and checked by `visibility-probe.m`.

Model-free replay uses `pnpm qwen17:context:report --run benchmarks/runs/qwen17-accessibility-v1/window --out /absolute/new-summary.json` and `pnpm qwen17:context:test` (`make qwen17-context-report RESULTS=... OUT=...`, `make qwen17-context-test`). Review judgments bind input/observation/output hashes. Missing reads, altered outputs and leaked canaries reject completion. The [completed report](../../results/qwen17-accessibility-v1/README.md) records the fresh paired run and selection outcome.

## Protocol failure and combined pipeline

The original completed 236-observation comparison is retained under [pre-envelope](../../runs/qwen17-accessibility-v1/pre-envelope/summary.md). It exposed language metadata in some delivered Qwen transcripts. `token-probe.go.txt` records a real SDK result with initial token `" language"`, followed by the language and `<asr_text>`. Pinned sherpa-onnx code requires its decoded metadata prefix to start exactly with `"language "`, so this leading space defeats native envelope removal. `qwen-utils.py.txt` retains the official trimmed metadata/text parsing contract. `protocol-diagnosis.json`, the old sources and final adapter sources preserve the evidence. The fix parses transport metadata at the ASR boundary and preserves ordinary/literal transcript text; it changes no weights, model prompt, seed or decoding parameter. Three actual previous-leak cases verify the corrected native adapter. A fresh full comparison is reported separately from this original run.

The [combined diagnostic](../../runs/qwen17-accessibility-v1/integration/summary.json) adds actual native ASR on the [12 speech fixtures](../../corpora/asr-window-v1/README.md), then the same installed final-only rewrite worker with actual collected window text. Old arm: X-ASR finalizer plus OCR. New arm: Qwen3-ASR 1.7B finalizer plus Accessibility. Both apply the existing rule correction and cleanup. Recorded window text is replayed into the final request; earlier stable-recognition evidence and live preview are not replayed in this final-only driver. No prompt was tuned on these outputs. Review preserves case-sensitive identifiers, names, negation, uncertainty and material constraints; harmless punctuation changes pass. The 10/12 versus 8/12 judgments are assistant inspection and are not independent semantic accuracy estimates.

Replay both text and combined-stage checks with `pnpm qwen17:context:report --run benchmarks/runs/qwen17-accessibility-v1/window --integration benchmarks/runs/qwen17-accessibility-v1/integration --out /absolute/new-summary.json`. The reporter verifies that rewrite inputs use the recorded ASR result and actual paired screen text. `source/` and `source-final/` retain code before/after protocol parsing; file maps and the final archive preserve byte identities. Weight/runtime paths in driver configs are historical identities requiring explicit local provisioning.
