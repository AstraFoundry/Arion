# English admission native validation

The source-frozen macOS arm64 run at `0db60e55` passed all 57 actual Rime/AppKit suite cases. The admission groups cover 20 development, 17 inspected regression-validation and 12 fresh holdout inputs on both five/nine-slot menus: 98 input/page checks. Positive cases select the actual engine candidate and verify one commit; negative cases check Chinese priority and the absence of unwanted English. The runtime still retains complete source lookup and case alternatives.

`native-final.json` contains per-input native candidate traces, compiled binary identity, all IME source identities, runtime manifest identity and platform boundary. `provenance.json` pins every retained original output plus corpus/host/policy metadata. `keyboard-final.log` retains the full local check output. Exact fixture bytes and reproduction steps are in the [corpus](../../corpora/ime-english-admission-v1/README.md).

Earlier `native-first.json` and `native-second.json` retain failures that exposed rare exact-word admission and weak-Chinese ordering defects. The first run also overlapped another task's Shift edits and is not a valid source-frozen comparison. `native-third.json` and `native-holdout.json` retain subsequent observations before the final source-freeze guard. These earlier diagnostics have no guaranteed exact source identity and support no comparative accuracy claim. The holdout was frozen after policy corrections, before its first execution; subsequent use is regression validation.

This is a small authored functional validation, not an estimate of real-user accuracy, a latency benchmark or installed IMK acceptance. The [Windows CI keyboard step](https://github.com/AstraFoundry/Arion/actions/runs/40739741505) passed the same 98 input/page checks on a real standard-user desktop at the same code revision; its original stdout/stderr are retained here. The log also records actual candidate selection/commit assertions passing in the shared native executable. Windows native module and owned-window gates passed. Installed TSF dispatch remains separate. Full-workflow packaging status is not implied by these keyboard results. Vendor mechanisms and adopted-policy limits are described in [research](../../../docs/research/english-candidate-admission.md).

Replay retained hashes, per-input candidates and exact-once totals with `node scripts/verify-english-admission-evidence.mjs`. Replay does not execute an OS input method or measure latency.
