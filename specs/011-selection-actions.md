# 011 Selection actions

The selection popover's data, URL rules, native read/copy/vocabulary path, the popover view, its onboarding page and its settings card. [ADR 048](../docs/decisions/048-selection-action-urls.md) owns the URL boundary.

## Requirements

SEL-01: Selection preferences live on the existing preferences record. `Enabled` is off when missing, including profiles written before the field existed. The two built-in clients are `claude` (`claude://claude.ai/new?q={{text}}`) and `chatgpt` (`codex://new?prompt={{text}}`). Both stay off until enabled. A nil action list means the built-in list, in menu order: translate-zh, explain, summarize, rewrite, ask, ask-chatgpt, copy, add-vocabulary. Titles are not stored. Normalize drops an unknown client, resets a template that is not the built-in for that id, and keeps `PreferencesVersion` at 1. The disable menu (SEL-08) writes `pausedUntil` (Unix seconds; missing or 0 is not paused), `disabledApps` (app identifiers, bundle identifiers on macOS) and `disabledSites` (http(s) hosts) on the same record; all three are omitted when empty, so older profiles stay valid.

SEL-02: `{{text}}` is the encoded prompt or the raw selection. Prompt bodies are the built-in English instructions. A prompt goes to the chosen client, or to the first enabled client when none is named. A client action sends the selection unchanged and only to its own client. The filled URL is percent-encoded. Only `https`, `claude`, and `codex` are allowed, and an `https` URL must not carry userinfo. `http`, `javascript`, `file`, `chatgpt`, `doubao`, `feishu`, and any extra `{{...}}` placeholder are refused. The Claude query is capped at 14,000 Unicode characters before encoding. ChatGPT is not capped. Filling a URL does not launch a process, send a key, or run a shell or Apple event.

SEL-03: A mouse-up reads the focused selection only while the master switch is on and the bar is not paused (SEL-08). A release over the shown popover is a choice inside it and reads nothing, so the question field taking the keyboard does not close the popover. macOS reads the focused element of the frontmost app, never of Arion: a text field's Accessibility selected-text read first, then, for page text that is not a text field, the selection of the enclosing `AXWebArea` through `AXSelectedTextMarkerRange` and `AXStringForTextMarkerRange`, anchored by `AXBoundsForTextMarkerRange`. Secure input and an `AXSecureTextField` produce no text on either path. Neither path posts Command-C or reads the clipboard. Windows uses UI Automation `TextPattern.GetSelection` and returns that text. The dictation hold key and the Windows visible-range script are not this reader. A secure field produces no offer and no text. An empty selection produces no offer. For a non-empty, non-secure selection the platform also names its source: on macOS the frontmost app's bundle identifier and display name, and the http(s) host of the web area holding the focus, read like the scene target's peek, with no field text and no host of a secure field; Windows names neither yet. A source in `disabledApps` or `disabledSites` produces no offer. The source stays in memory with the offer and is stored only when the user disables the bar there. The selected text is not logged. A permission denial may be recorded as `selection_watch` with a stable code only. An offer opens `uiapp.Selection`, sized by `SelectionHeightFor` and, until the bar has measured itself, `SelectionWidth` (400) or the last measured width, in a nonactivating flyout beside the selection rectangle, or beside the pointer when that rectangle is unavailable. The flyout does not take the editor's focus. Master switch off, an empty selection, and a secure field close the popover and add no vocabulary entry. Copy, vocabulary, and open use the existing clipboard writer, `AddHotword`, and the OS URL opener.

SEL-04: Copy writes the captured selection with the existing clipboard writer. Vocabulary saves it with `AddHotword`. Both refuse a secure field before writing. The action rechecks the field at perform time and still writes the captured offer text.

SEL-05: Launch uses the operating system's URL open (`/usr/bin/open` on macOS, `ShellExecuteW` on Windows) on a URL that already passed SEL-02. The opener's error does not include the URL.

SEL-06: The popover renders the offer's actions as given and builds no URL. It is dark in both appearances. Its first surface is a bar `SelectionHeightFor` (37) DIPs tall and as wide as its buttons: one row of the enabled clients in the offer's `Clients` order (Claude, then ChatGPT), each opening the second menu, then copy and Add to vocabulary, which act at once, then an X labeled Disable options that opens the disable menu (SEL-08). The prompt rows are not on the bar. The view reports the bar's measured width, or an open menu's or a failure line's where wider, and the window takes that width, so no empty space follows the X. Choosing a client opens a second menu, `MenuWidth` (224) DIPs wide, beneath the bar; choosing it again closes it, and Escape closes it while it has the keyboard. The menu lists the prompt rows in offer order, the `ask` question field, then that client's own actions (Ask ChatGPT under ChatGPT). Every prompt and the question go to the chosen client. The first prompt row is highlighted and carries a Return glyph named Return; Up and Down move the highlight, and Return runs the highlighted row. With no menu open, Return copies. Clicking the question field focuses it and keeps the menu open; submitting a non-empty question opens `ask` with it. A client with nothing to list is not on the bar, and the bar shows no client when none is enabled. A failed action shows its reason beneath: an invalid hotword shows the vocabulary term rule, a secure field the secure-field message. Motion uses the shared presets: bar and menu buttons fade their hover and chosen fills (`Quick`) and sink to 0.96 while pressed (`kit.Press`); a client's chevron turns up while its menu is open (`Disclosure`); a menu comes down 6 DIPs from the bar, fading and scaling from 0.96 at the corner under the control that opened it (`Pop`), and leaves over 160 ms, during which the window keeps the menu's size. Reduce Motion applies MyGo's reduced motion.

SEL-08: The disable menu opens `MenuWidth` DIPs wide under the X, at the bar's trailing edge, as Feishu's selection toolbar menu does; choosing the X again or Escape closes it, and opening a client's menu closes it. Its rows, in order: Disable for 1 hour (`SelectionPause`, 60 minutes), Disable on the offer's site, when SEL-03 named one, Disable in the offer's app by display name, when named, and Turn off selection actions. Choosing a row calls `DisableSelection` with `pause`, `site`, `app` or `all`; the backend saves the change through `UpdatePreferences` and dismisses the bar. `all` turns `Enabled` off, which stops the watch as the settings switch does. A failed save shows the generic failure line. The menu has no Knowledge AI or settings row.

SEL-07: Onboarding ends with a selection page after translation, where the platform has a selection reader (DSK-14). Its master switch starts off, and the Claude and ChatGPT rows appear beneath it once it is on. Leaving the switch off is a valid answer: Finish stays enabled and completes setup. Settings › General carries the same switch and client rows. Both write `Preferences.Selection.Enabled` and the client flags through `UpdatePreferences`. The ChatGPT row states that it prefills a local chat through `codex://`.

## Acceptance

- SEL-A01: Defaults stay off. An old preferences file without `selection` stays off. Normalize repairs a foreign client id and a non-built-in template without changing the preferences version. A pause reads nothing until `pausedUntil` and offers again after it; a disabled app or site gets no offer while another app does; each disable scope is saved by `DisableSelection` and dismisses the bar.
- SEL-A02: Encoding, the Claude length cap, a refused scheme, and a missing client fail in portable tests. Those tests do not launch Claude, ChatGPT, Doubao, or Feishu.
- SEL-A03: On macOS, with `ARION_E2E_SELECTION=1` and existing Accessibility access, the production reader returns a known selection from the owned editor. Mouse-up opens the popover with that text and the offer's action ids in menu order. Copy leaves the string on the clipboard. Vocabulary reopens with that hotword. A secure field and an empty selection produce no popover and no vocabulary entry. The client URL equals the filled template. The master switch calls no reader and opens no popover. Selected text is absent from the logs. Missing access fails the test.
- SEL-A05: `go test ./ui/app` renders, in both locales, a fresh profile reaching the selection page as the last step with the switch off and Finish enabled, Finish completing setup with the switch left off, the page omitted without a reader, the bar holding the clients, copy, vocabulary and the X in one row with no prompt row and the reported width ending at the X, the disable menu's rows under the X calling `DisableSelection` with each scope and omitting the site and app rows without a source, a menu coming in over its first frames and the window keeping its height while a menu leaves, a client opening the second menu with `translate-zh` highlighted and run in that client on Return, the `ask` field staying open on click and asking that client, Ask ChatGPT only under ChatGPT, the menu closing back to the bar height, no client and no menu when no client is enabled, and the General card writing `Selection.Enabled` and a client flag.
- SEL-A04: On Windows, the same outcomes use `GetSelection` text from the owned `ArionOwnedEditor`. The test does not post Ctrl+C, inject a keystroke, or launch a client.
