# 012 Mobile input

The iOS keyboard extension and the Android input method ([ADR 051](../docs/decisions/051-native-mobile-keyboards.md)). Product behavior follows the desktop where a phone allows it; the differences are stated here. Implementation status is in [mobile apps](../docs/project/mobile.md).

## Requirements

- MOB-01: The keyboard offers one microphone, the language key when more than one recognition language is chosen, delete, space, return and, where the platform asks for it, the next-keyboard key. Tapping the microphone starts dictation; tapping again finishes. Holding the microphone dictates until release; releasing over cancel discards the dictation and releasing over translate translates it.
- MOB-02: While listening, the recognized text appears in the keyboard: finalized text in ink, the tail the recognizer may still revise muted. The editor receives nothing until the dictation ends, and then exactly one insertion at the caret focused at that time. A space is added between Latin words; none between CJK text.
- MOB-03: Cancel, dismissing the keyboard (on Android also leaving the field) or starting another dictation invalidates the dictation in flight. On iOS a caret move inside the same keyboard session keeps it, and the text goes to the caret focused when it ends. A late recognition or model result cannot insert text.
- MOB-04: Recognition runs on the device's on-device recognizer, for the chosen language. Audio never leaves the device. A missing model, an unsupported language, a busy recognizer, lost microphone and empty speech each end the dictation with their own message; a missing model starts the system's download, and the keyboard shows the language and its progress until it can dictate.
- MOB-05: With polishing on (the default), the rule-corrected transcript is rewritten by the chosen engine (the on-device model, or the cloud model the user connected, MOB-14) with the desktop's formatting recipe and scene rules, bounded to 15 seconds, and the output must pass the desktop's delivery check. If the model is unavailable, refuses, fails the check or times out, the rule-corrected transcript is inserted with the notice “Inserted without polishing.” Settings explains when the device cannot polish.
- MOB-06: Translate produces the chosen target language (the desktop's twelve targets) from the same recipe. When translation cannot run, the source-language text is inserted with a notice.
- MOB-07: The scene follows the field: a search field gets search finishing; an e-mail subject (Android) gets e-mail; everything else chat.
- MOB-08: Vocabulary terms bias recognition (`contextualStrings` on iOS, biasing strings on Android) and are kept as written by polishing. History is off by default, keeps at most 100 dictations on the device, and turning it off erases it. Android fields that request no personalized learning are never kept. Neither is included in device backups.
- MOB-09: iOS: dictation requires Full Access, explained in onboarding; without it the microphone shows how to turn it on. Microphone and speech permissions are requested by the app, as soon as onboarding reaches the microphone step. Android: password fields disable the microphone; RECORD_AUDIO is requested by the app.
- MOB-10: Onboarding asks for one thing per step, with its progress shown: what Arion does with the optional account (MOB-13), the microphone, adding (and on Android selecting) the keyboard, polishing (off, this device or cloud), then a practice field. Android skips steps already done when the user returns from Settings. On iOS the steps for adding the keyboard live on Arion's page in the Settings app (its Settings bundle), under the system's Keyboards row, where the user follows them; onboarding opens that page and does not repeat them.
- MOB-12: The app has five tabs, the phone's share of the desktop's Settings sections: Overview, Dictation, Polish, Vocabulary (with history) and Account (with the version). It opens on the Overview, as the desktop's: time dictating, words, words polished, average speed, daily words over recent weeks, words by scene for today, the last 7 days or all time, and the latest vocabulary. Before the first dictation it shows what will collect there and how to start. The keyboard records each committed dictation as its day, listening time, word count (the desktop's counting) and, when polished or translated, its scene; never text.
- MOB-13: Signing in to AstraFoundry is optional. Onboarding offers it with the terms checkbox (checked; unchecking disables sign-in), the usage-sharing checkbox (unchecked) and Continue locally. The account page shows the profile, the usage-sharing switch, the portal links and Sign out, or Sign in. A checked usage box records consent only after a successful sign-in; consented daily counts are reported as on the desktop. Restarting restores the account without a browser.
- MOB-14: Polishing can run on this device or on a cloud model connected with an API key (OpenAI, Anthropic, Google Gemini, DeepSeek, OpenRouter, OpenAI or Anthropic compatible). Connecting lists the provider's models before the key is saved; a new provider starts on its fast model. Only the rule-corrected transcript and the recipe are sent, and only to the provider in use.
- MOB-15: iOS: the keyboard also types, on the desktop's pinned Rime engine with schemas prebuilt on the build machine; nothing is deployed or downloaded on the phone ([ADR 053](../docs/decisions/053-mobile-rime-typing.md)). The voice/typing switch is the top-right key of both panels and the hide key the top-left; the panels share one height, so neither moves, and the bottom row starts with 123 as on the system keyboard. The 中/EN key toggles Chinese and English only; whether Chinese uses the full keyboard or 9-key is the Dictation tab's Chinese keyboard setting. Return shows an icon unless the field names an action. A composition stays in the keyboard until a candidate, space or Return commits it; moving the caret or hiding the keyboard drops it. Chinese learning is stored encrypted with a device-only key.
- MOB-16: iOS: the Dictation tab offers microphone gain (off, +3, +6, +9 or +12 dB; off by default), applied to the captured audio before recognition with clipping at full scale.
- MOB-11: Copy comes from `packages/mobile-strings` in English and Simplified Chinese. Colors, radii and spacing come from Sunbeam's generated tokens; keyboard keys are raised and app surfaces flat.

## Acceptance

| ID | Scenario and required result |
| --- | --- |
| MOB-A01 | Practice field → Arion keyboard → tap microphone → speak → draft visible in the keyboard and not in the field → tap again → one insertion |
| MOB-A02 | Hold microphone → speak → slide over cancel and release → nothing inserted; repeat, release over translate → the target-language text is inserted |
| MOB-A03 | Start listening → dismiss the keyboard (Android: or change fields) → the dictation ends; nothing arrives later |
| MOB-A04 | iOS without Full Access → tap microphone → Full Access message, no capture |
| MOB-A05 | Model unavailable or polishing refused → rule-corrected text inserted, notice shown |
| MOB-A06 | Silence → “Didn't catch that.”; no insertion |
| MOB-A07 | History off → dictate → nothing recorded; on → entry with copy and delete; off → entries erased |
| MOB-A08 | Android: Arion enabled and selected in Settings → return → onboarding advances to practice |
| MOB-A10 | No dictations → Overview shows the first-run card; dictate → time, words and the day's activity update; polished dictations appear under their scene |
| MOB-A11 | Onboarding → uncheck terms → sign-in buttons disabled; Continue locally → microphone step with no network request |
| MOB-A12 | Polishing → Cloud → paste a rejected key → refusal shown, nothing saved; a valid key → models listed, fast model chosen, next dictation polished by that provider |
| MOB-A13 | iOS keyboard → keyboard key → type `nihao` → 你好 first; choose it → inserted. Set 中文键盘 to 九键 → 64426 → 你好; 中/EN toggles 九键 and English only; the top-right switch and top-left hide keys keep their place across panels |
| MOB-A09 | `pnpm mobile:check` passes; `pnpm ios:test` and `pnpm android:test` pass |
