# 007 Configurable IME and local candidate ranking

## IME integration

IME-01: On supported systems, onboarding offers optional input-method setup after Accessibility; users may defer to Keyboard settings. Both surfaces reuse explicit install, enable/retry, switch and status controls. Installation is distinct from app startup and shows immediate progress. Continue requires actual selection and completed activation; copied, registered or enabled alone is not completion. In-flight file replacement cannot be skipped; activation may be cancelled or deferred. Unsupported systems omit setup in both directions.

An explicit installation of a missing source continues into a bounded activation attempt; updating an existing host preserves prior selection without starting an unrelated setup attempt. Activation validates installed bytes, subscribes to enabled/selected-source notifications before requesting registration/enablement, queries discovery, enables parent before child, observes actual enablement, selects the child mode and verifies actual selection plus the expected executable's host connection. The attempt has a 30-second deadline; host connection is separately bounded to 15 seconds within it. Notification wakes observation, with 250 ms polling to cover coalesced/missed notifications and non-UI clients. A notification alone does not establish that Arion changed. Enablement is requested once per attempt; selection can retry within its deadline. Background refresh never registers, enables or selects. Repeat clicks cannot create competing attempts.

The UI distinguishes copied/not discovered, registered/not enabled, enabled and selected. A successful register request whose source is not yet discovered retains validated installed bytes for observation/retry. A successful enable request with a disabled source remains pending. Real copy/register/enable API errors retain transactional rollback during replacement; retrying activation never recopies or removes the installed bundle. Stage-specific discovery, enablement, selection and connection failures retain recovery actions. Native authorization stays visible without automatic Settings navigation; modern authorization success is observed, never inferred from an API return. Explicit Keyboard settings help remains available after incomplete setup.

Cancellation, deferral, leaving setup, closing its window and quitting revoke continuation; cancellation is checked immediately before queued native selection. Cancel retains files and OS authorization. Worker completion releases its busy guard; stale completion cannot overwrite a newer attempt. Install/update/remove are excluded while activation is running. The installer verifies Developer ID signature and default Data Protection identity before replacing installed bytes; activation validates the installed payload too. Unverified development payloads fail with release-package guidance. External OS changes refresh status without restarting Arion. Removal switches away, attempts public disablement in a signed short-lived maintenance process, and requires agreement between local and fresh independent source observations before stopping the host and deleting bytes. A disabled parent makes its child unavailable even when the child's enabled flag remains set. Policy denial, unknown state or disagreement retains the installed bundle and exposes System Settings recovery; `noErr` alone never permits deletion.

IME-02: macOS uses an InputMethodKit server bundle/client composition; Windows uses a TSF text service with edit-session locks, COM apartment/lifecycle and correct architecture registration. A MyGo window is neither an IMK server nor a TSF service. Shared contracts cross the host boundary through documented authenticated/local IPC when separate processes are required.

IME-03: Active voice composition owns its host range and revision. Partial hypotheses update marked/preedit text only inside that range. Candidate selection, Enter/confirm, Escape/cancel, deactivation and focus loss follow platform semantics. No recognizer thread writes into the editor directly.

IME-UPDATE-01: Startup detects a bundled update and automatically maintains an existing enabled source when no dictation or maintenance is active. Never reinstall a removed source or enable a disabled source from polling. A failed attempt stops automatic retries for this app run and offers explicit retry. macOS and direct legacy Windows registrations recheck selection after staging and defer selected-source maintenance until normal source switching. Windows stable-loader installations may atomically publish a fully verified protected versioned core while selected, preserving profile/category registration, user enablement and active composition. Live objects, calls and locks MUST prevent core unloading. A cached processor facade MUST release its delegate on deactivation and resolve the published core on a later activation when the old core is safely releasable. Already loaded direct legacy objects retain their original native lifetime; registration changes MUST NOT be presented as upgrading those objects in place. Updating an installed macOS input method MUST stage and validate new bytes before interrupting the current host, for explicit updates cancel owned voice composition and switch away without disabling authorization, and confirm old-process exit before replacement. Registration, prior selection and a connection from the expected executable build MUST be observed before operational update success. A pending first-install authorization remains separately pending. Failure MUST stop the failed replacement before rolling files back; an unkillable replacement MUST preserve recovery copies and report failure. Desktop restarts MUST recover a refused orphaned IPC endpoint while retaining live sockets and unrelated paths. A transport failure MUST NOT claim that the OS input source is unselected.

IME-04: A host refusing composition/read/write or a secure field produces an explicit capability result. Do not switch secretly to clipboard/keystrokes. Both native hosts implement the shared offline full-Pinyin keyboard defined below; host shortcuts and English-mode typing pass through according to the OS contract. Implementation and acceptance status remain separate from this requirement.

IME-05: Candidates must support keyboard navigation, selection, accessible names and bounded display. Selected ID/revision survives a reorder only while still present; user navigation freezes automatic selection until the next explicit composition update. Windows candidate placement anchors to the start of the current conversion, rather than following the moving preedit caret. Continuous typing, editing, paging and partial selection keep that anchor until conversion ends or is canceled; the next conversion acquires a fresh anchor. Geometry follows current text-layout notifications through read edit sessions after document writes, without an intermediate hide/show caused by querying unfinished write-session layout. Windows candidate text and number labels use privately bundled Source Han Sans SC with grayscale antialiasing on a premultiplied-alpha surface. The candidate bar has antialiased rounded outer and highlight corners, compact measured cells and smaller number labels vertically centered against the visible candidate glyphs. Temporarily unavailable or clipped geometry hides the panel; valid current geometry restores it without stale coordinates or a document write. Acceptance checks visibility after each composing key in ordinary and rich browser fields, delayed layout recovery, scrolling/clipping and invalidation on focus/context/revision changes; a successful final commit alone does not establish candidate visibility.

IME-06: The macOS input menu's first item is Voice input, titled with the configured dictation key ("Voice input (Right Option)" / "语音输入 (右 Option)") and separated from the keyboard items. Choosing it sends an activation-bound `dictate` message; the app toggles dictation exactly as its tray item does (idle starts, capturing stops, preparing cancels, finalizing reports busy), and the delivery route is still selected per [DSK-01](001-desktop-input.md). The item is disabled while the host has no connection to the app. A `dictate` with a stale or empty activation, or from a replaced connection, is ignored. The app writes the dictation key to `keyboard.json` as `dictationKey`; the host reads it on activation, and an absent or unknown key leaves the key out of the title.

## Windows native host

Windows registration enables the machine profile by default without choosing the user's default keyboard. Enablement requires both the user preference and the TSF catalog enabled flag. An explicit activation may repair an older disabled machine registration once, with administrator approval and validated installed bytes, then reapply user enablement; it never copies or replaces a DLL. Background observation cannot initiate repair. Selection succeeds only after the exact Arion profile is observed active.

The parent/child authorization and signed bundle lifecycle above describe macOS. Windows setup uses an x64 native COM service and machine-protected, hash-versioned Program Files payload; installation/removal and protected version publication respect administrator approval, while enablement is per user. The shared keyboard's profile is **Chinese (Simplified, China) → Arion** (`0x0804`), with the existing Arion CLSID/profile GUID retained. The older **English (United States) → Arion Voice** (`0x0409`) profile must be identified as requiring migration, not reported as a current installation. Migration and normal version updates use the shared automatic-maintenance policy: validate and stage a complete independent version, compare expected previous registration, defer selected/disabled/absent sources, switch the owned COM/current profile and retire only the owned legacy profile. Keep loaded old closures and user data intact; normal failure rolls registration back and an interrupted transaction remains observable until completed. Do not require separate user removal/reinstallation or repeat authorization after denial. Windows Keyboard settings expose the shared Pinyin/candidate preferences as well as the source lifecycle. Visible switcher discovery and actual editor input require independent acceptance.

Windows setup observes registration, enablement and selection without requiring an editable client inside the settings window. Each dictation separately requires the expected DLL build and acknowledgement of successfully acquired TSF composition before microphone capture. Source/transport observation failure cannot silently choose external-editor delivery. Native composition owner refusal, password/read-only fields and unsupported process architecture/integrity fail explicitly. A transitory text store is eligible only when writable and exposing an explicit usable non-password input scope; the lifetime flag alone does not imply an unsafe field.

Local Windows keyboard input supports medium- and high-integrity x64 desktop processes with real TSF text stores, including elevated applications and UAC-disabled desktops ([ADR 028](../docs/decisions/028-windows-keyboard-host-admission.md)). Low-integrity, AppContainer, system-integrity and secure-mode hosts remain refused. New keyboard profiles and mode files must remain current-user-owned even when created by elevated tokens; untrusted existing paths remain refused. Voice composition supports only ordinary unelevated medium-integrity hosts; elevated keyboard hosts must not connect to its pipe and must disable their Voice input action. The same-user named pipe also binds Windows session and ordinary peer integrity; a lower-integrity desktop process cannot gain text access to an elevated editor. Original selected text is restored on cancellation/platform termination only while the native range still contains the host's own draft; user edits win. Every write revalidates owned range/caret independently of notifications. Windows updates never overwrite loaded DLLs. An editor retaining an old COM factory can continue on the retained old closure until reopened; voice sessions from a mismatched build remain refused rather than being reported as operational update success.

## Shared offline keyboard typing

The following typing, candidate, mode and learning behavior applies to both native hosts. macOS uses InputMethodKit/AppKit and Keychain/CryptoKit; Windows uses TSF/native candidate windows and current-user DPAPI. Engine/session, candidate mapping, key policy, ranking and learning transaction logic must share production sources and pinned schema/data, with separate native binaries. Platform packaging requirements in KBD-06 remain distinct: universal arm64+x86_64 on macOS, x64 DLL/runtime closure on Windows. Native implementation and acceptance on Windows are in progress; these requirements are not a shipped-capability claim.

KBD-01: The installed native input-method host provides Simplified Chinese full-Pinyin conversion without the main desktop app or network. Pin independently licensed engine/data bytes and complete schema dependencies. Missing/corrupt runtime/data is an explicit unavailable state, never simulated conversion or silent Latin substitution.

KBD-02: Keep raw input/caret, selected segments, suffix, displayed preedit and final committed text separate. Support full Pinyin, apostrophe boundaries, abbreviation and v/ü input through the declared schema. Direct `ü`/`Ü` key characters map to the schema's `v`/`V` spelling in Chinese mode; English-mode and host-shortcut pass-through preserve the original event. Candidate choice can consume a prefix and continue conversion of the remainder. Only an actual engine commit reaches the client. Ordinary punctuation and symbols commit directly without opening symbol candidates; Chinese quotes alternate opening/closing forms. Apostrophes inside Pinyin retain syllable separation, and existing candidate paging keys keep their navigation behavior during composition.

KBD-03: Provide bounded candidate pages, stable page-relative number/mouse selection and keyboard navigation. Once expanded, the candidate grid stays expanded throughout the current composition, including partial selection with a remaining suffix and subsequent input or edits. A candidate refresh resets the page and highlight to the first row without folding the grid. Explicit collapse remains available; a completed commit, cancellation or ownership loss clears expansion for the next composition. Backspace/Delete, arrows and Home/End operate on the engine's composition; partial-selection rollback must be verified. Stale candidate UI callbacks cannot choose a newer revision. Enter commits raw input according to the configured schema; Space selects the highlighted candidate; Escape cancels.

KBD-04: Chinese/English switching uses a standalone left/right Shift press released in less than 0.3 seconds; the input menu and Shift+Space remain available. Other keys or modifiers during the press, long holds, cancellation and deactivation invalidate the pending switch. Duplicate notifications for the same Shift side/state must preserve the original deadline and produce at most one switch; an unambiguous Shift-flag transition may identify a modifier event whose keycode is absent (`0`/`255`). Switching shows a nonactivating, click-through 23 × 23 point language badge beside the host caret for 1 second, with a solid rounded surface, no window shadow and immediate show/hide; inside it the label flips from the previous mode to the new one around the horizontal axis (two 0.12-second halves, none under Reduce Motion); typing, voice takeover and focus loss dismiss it. A missing caret rectangle suppresses the badge. Switching and deactivation discard unconfirmed composition. Command-modified host shortcuts relinquish ownership before pass-through. Keyboard and voice drafts never share a mutable owner; voice start, physical typing, focus changes and late socket callbacks cannot overwrite another owner's range.

KBD-05: Learn only confirmed candidate selections through an encrypted local user database with an OS-kept key. Cancellation/stale results do not learn. Restart persistence, reset/delete and encrypted backups are explicit operations. Missing keys, authentication failure and write failure do not create a new vault or plaintext storage. No raw key history or selected text enters diagnostics or account sync.

KBD-06: Ship a universal arm64+x86_64 input source with relocatable native dependencies, all notices and prebuilt data. Schema deployment/download must not run on the typing path. Actual editor behavior, offline first activation, word/sentence quality and key-to-preedit latency require host observations; unit or engine-only results are insufficient.

KBD-07: Chinese mode offers two independent switches, both off by default. Full width commits unconverted ASCII letters, digits, space and symbols as full-width forms (`1` → `１`, Space → U+3000); Pinyin letters still compose and Chinese punctuation is unchanged. English punctuation passes ASCII punctuation through instead of the Chinese table; quote alternation does not apply. With both on, punctuation commits the full-width ASCII form (`.` → `．`). English mode passes keys through unchanged under either switch. The input menu names each item by its action (Use full-width/half-width characters, Use English/Chinese punctuation (⌃.)); Ctrl+. switches punctuation in Chinese mode and passes through in English mode. Full width has no shortcut because Shift+Space is KBD-04's language switch. A switch discards unconfirmed composition and shows the KBD-04 caret badge turning over to the new state. The input method owns both choices in its user directory, shared by all clients; restart retains them, an absent file means the defaults, and a choice that cannot be saved is refused and leaves the option unchanged.

KBD-08: macOS and Windows Chinese Pinyin can show Unicode Emoji alternatives for exact full-suffix Chinese candidate words. The offline index is generated reproducibly from pinned CLDR Simplified Chinese names and closely formed keywords, limited to fully-qualified Unicode Emoji 15.0 sequences for the macOS 14 baseline; actual OS rendering remains an acceptance gate on each platform. A small reviewed Arion alias list overrides ambiguous common words. The generator rejects changed upstream bytes, single-character automatic triggers and skin-tone variants; it omits ambiguous keyword-only triggers and a small reviewed set of polysemous words. Each generated trigger contributes at most one Emoji candidate. The default-on `emojiSuggestions` preference lives in app-owned `keyboard.json` and is read on activation; English mode, mid-input caret, unmatched words and selected/confirmed segments produce no Emoji alternatives. Returning the caret to the suffix end refreshes eligibility. The native Rime candidate has its own type, source range and engine index; selection commits that candidate through the normal engine path. The first three displayed slots remain Chinese text, at most two Emoji appear on the first page, and Emoji never enters Chinese context ranking or Chinese learning. The candidate panels render Emoji with installed system fonts; no Emoji artwork, font or rime-emoji dictionary is bundled. Windows Chinese text uses the privately bundled font specified in IME-05. Windows uses Segoe UI Emoji through DirectWrite/Direct2D color-font drawing and offers a sequence only when the installed font shapes it as one complete color glyph. Missing glyphs, decomposed ZWJ sequences and unsupported flags are omitted without changing the Chinese text order. Windows refreshes the shared preference during active composition and invalidates old candidate callbacks. Native TSF edit, rendering and installed-editor acceptance remain separate evidence gates.

KBD-09: Chinese mode offers offline English words and prefix completion without switching modes. The complete pinned ESDB70 A/B/Z variant-1 and CSpell lexicon retains source case, lowercase lookup and observed counts separately; membership is independent of frequency. Grouped TSV v2 and disjoint rank indexes provide exact, suggestion and full deferred lookup lanes. Automatic completion requires at least three typed letters, half-word coverage and 1,000 observed source occurrences; these are versioned Arion policy settings, not neural probabilities. Strong Chinese evidence requires an actual full-range dictionary word and a normal full-input spelling path from the packaged Rime Prism, excluding abbreviation/correction/completion paths. With strong Chinese evidence, protect up to three Chinese words, expose familiar native-lowercase exact English, then preserve Chinese before deferred English. Without it, exact English and admitted completions precede abbreviated/partial Chinese; when English evidence exists, remaining lookup and Chinese tails interleave one English/two Chinese, otherwise weak lookup follows Chinese. There is no fixed English preview quota. Exact case alternatives and every deferred prefix key remain selectable through actual lazy engine pagination without full-prefix scans. Editing, punctuation, raw Enter, cancellation/revision ownership and Chinese-only learning remain intact. Both packages require matching data, source pins and complete notices; malformed data or unavailable spelling Prism rejects startup. Typing performs no deployment or download.

## Local scoring

RNK-01: Sources may be actual recognizer alternatives, a documented phonetic/lexicon engine, or approved dictionary-derived alternatives with explicit provenance. Their absence yields a one-item set; never invent ASR n-best or neural probabilities.

RNK-02: Input carries session/generation, composition revision, exact candidate IDs/text/source, bounded approved context and language hint. Output is a permutation of the same IDs plus optional finite comparable scores. It cannot generate words or alter candidate text.

RNK-03: Scoring is cancellable, entirely local and triggered only for a supported composition revision. Stale results cannot reorder newer candidates or replace committed text. If unsupported/unavailable, preserve producer order and show capability state; this is an explicit mode outcome rather than hidden inference fallback.

RNK-04: Evaluation must compare producer order and authorized vocabulary boost against a learned ranker. Embedding similarity is not automatically a homophone-aware likelihood score. Cross-encoder query/document relevance is not automatically IME quality. Jev is TypeSafe’s decision model; Laya Multilingual is the initial local Choice evaluation candidate. Its training task, typed-head/tokenizer export parity and candidate calibration need evidence before adoption.

RNK-05: Short candidate ranking must coexist with ASR without breaking audio deadlines. Ranker maximum candidates/context length, memory and timeout are configuration with benchmarked limits. Don't deploy a large generation model solely because it can assign a number.

Voice IMK ownership is implemented; full-Pinyin keyboard implementation and host acceptance are in progress. Keyboard candidates have a local context ranker (ADR 017): a permutation of the engine's leading candidates by the user's own confirmed (previous word, word) pairs, never promoting a shorter prefix, with engine order when its store is unavailable. On authored context homophones it lifts later-occurrence top-1 from 32% to 89% against engine order with frequency learning ([results](../benchmarks/results/imk-context-v1/README.md)); that is RNK-A04 evidence for this producer only. A deployed learned (model) candidate ranker is not claimed. See [handoff](../docs/project/agent-handoff.md).

## General LLM ranking experiment

The [general LLM alignment pilot](../docs/research/llm-ime-alignment.md) implements a separate keyboard snapshot contract, strict ID-only completion adapter, local worker completion operation and latest-request application scheduler. The installed keyboard still uses its existing native context ranker. Experimental drivers may use explicitly supplied synthetic fixtures and API credentials; they must not read personal input or stored subscription credentials. This does not authorize product cloud context or generated candidates, and RNK-02/RNK-03 remain the product boundaries. Real local results, initial rejected policy behavior and cancellations are retained under [benchmarks](../benchmarks/results/llm-ime-alignment-v1/README.md).
