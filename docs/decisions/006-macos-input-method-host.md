# ADR 006: macOS input-method host and local IPC

Status: Accepted; native implementation and isolated tests complete. Both ad hoc and Developer ID signed system input-source probes failed to select the source (IME-A01).

## Context

DSK-01/IME-01 require a user-selectable system IME mode. A MyGo window is not an InputMethodKit server (ADR 001), and recognition must stay in Arion's process with its resident models and session coordinator.

## Decision

- `ArionInput.app` is a small Objective-C InputMethodKit server shipped inside `Arion.app/Contents/Resources`. It contains no recognition. Its bundle ID is `si.astrafoundry.inputmethod.arion`, and it declares the Simplified Chinese input mode `si.astrafoundry.inputmethod.arion.pinyin`. [ADR 017](017-offline-pinyin-keyboard.md) adds independently owned offline Pinyin typing; engine/AppKit tests pass, while system input-source acceptance remains open.
- **Install and removal are explicit settings actions.** Install first validates the declared mode, Developer ID signature (all architectures and nested code), signed identity/default Data Protection entitlement consistency and embedded profile presence, stages the complete bundle beside `~/Library/Input Methods/ArionInput.app`, then replaces it. It explicitly registers the installed URL with LaunchServices before Text Input Sources, requests parent/child enablement and queries actual state. A registered source whose enable request returns success but remains disabled is retained as pending system setup; it is not reported ready. The app preserves the native authorization flow and provides an explicit Keyboard settings action plus adding/allowing instructions; the user then selects "Arion" through OS controls. A source missing after registration or an actual registration/enable API error remains a failure. A registration/enable API failure restores previous bytes and attempts to restore the previous registration state, reporting both errors if restoration fails. A filesystem rollback failure retains the previous bundle at the reported recovery path. Remove first selects the existing ASCII-capable keyboard layout if Arion is selected, verifies the switch and disables the source; only then does it delete the bundle and switch Arion back to shortcut mode. A failed removal preserves the chosen application input mode. Bundle copying runs off the UI thread; TIS registration, enablement and queries execute on the main thread under the SDK contract. Installation shows immediate progress and competing actions disabled; completion publishes pending/ready/failure on the main thread. A valid installed bundle not yet discovered by TIS remains pending instead of re-exposing Install. Polling refreshes externally changed activation state and records bounded state transitions without retrying enablement. Development payloads fail preflight before any installed-file replacement. Runtime preflight does not pin a publisher or replace the packaging gate’s profile authorization/CMS checks. Bounded diagnostic events record installation start/result, settings-open result and removal without raw errors or paths.
- **IPC** is a per-user Unix domain socket at `~/Library/Application Support/Arion/ime.sock` (mode 0600; only the same user can connect), one JSON object per line (bounded to 1 MiB). The IME sends `activate` (with the client bundle ID and a fresh activation ID), `deactivate`, session-scoped `escape` and `committed`; Arion sends `begin`, `mark`, `commit` and `cancel`. Every write is bound to the activation and session; marks also carry a strictly increasing revision. Replaced connections cannot alter the current session. Normal app quit closes the socket and clears the draft. Listener startup refuses an existing socket path rather than unlinking a potentially live server; a crash-stale socket requires inspection/removal before restart.
- **Ownership:** in `system_ime` mode the coordinator captures an IME target only while the source is active, mirrors every accepted draft revision into the owned marked text, commits the reviewed text once through `insertText` and waits for the IME's acknowledgement (`applied`, otherwise `unknown`). Cancellation, failure, Escape, ordinary user key edits, deactivation, disconnect and the host's `commitComposition` clear the owned marked text and invalidate the session; an unconfirmed draft is never committed implicitly (IME-03).

The build prepares the nested input-method app under a temporary sibling and publishes only the completed bundle by same-filesystem rename. Localized `InfoPlist.strings` includes the full child-mode ID so TIS resolves the product name. The visible destination never exposes an executable still being linked.

## Consequences

Voice dictation requires the menu-bar app. ADR 017 adds a standalone local keyboard runtime to the IMK host. The updated app and host must be deployed together; explicitly reinstall the bundled input source after updating the IPC contract. Transport race tests and an actual AppKit text-store harness verify ownership and Unicode behavior; they do not establish system input-source acceptance ([alignment report](../research/imk-typing-alignment.md)). Secure fields disable input methods system-wide, so no context can be read there. The speech recognizer still exposes no alternatives; the keyboard engine supplies its own lexical candidates independently of ASR and the optional RNK learned ranker. Windows TSF remains a separate task; on Windows the mode is reported unsupported rather than simulated.

## Alternatives considered

Running recognition inside the IME process (duplicate model residency, two recognizer lifecycles) and XPC services (needs signed, sandbox-aware bundles not available to ad hoc development builds).
