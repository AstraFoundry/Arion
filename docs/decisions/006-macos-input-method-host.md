# ADR 006: macOS input-method host and local IPC

Status: Accepted; native implementation and isolated tests complete. Both ad hoc and Developer ID signed system input-source probes failed to select the source (IME-A01).

## Context

DSK-01/IME-01 require a user-selectable system IME mode. A MyGo window is not an InputMethodKit server (ADR 001), and recognition must stay in Arion's process with its resident models and session coordinator.

## Decision

- `ArionInput.app` is a small Objective-C InputMethodKit server shipped inside `Arion.app/Contents/Resources`. It contains no recognition. Its bundle ID is `si.astrafoundry.inputmethod.arion`, and it declares the Simplified Chinese input mode `si.astrafoundry.inputmethod.arion.pinyin`. [ADR 017](017-offline-pinyin-keyboard.md) adds independently owned offline Pinyin typing; engine/AppKit tests pass, while system input-source acceptance remains open.
- **Install and removal are explicit settings actions.** Install first validates the declared mode, Developer ID signature (all architectures and nested code), signed identity/default Data Protection entitlement consistency and embedded profile presence, stages the complete bundle beside `~/Library/Input Methods/ArionInput.app`, then replaces it. It explicitly registers the installed URL with LaunchServices before Text Input Sources, requests parent/child enablement and queries actual state. A successful registration request whose validated bundle is not yet discovered is retained as discovery pending. A registered source whose enable request returns success but remains disabled is retained as enablement pending; neither state is reported ready. The app preserves the native authorization flow and provides an explicit Keyboard settings action plus adding/allowing instructions; an explicit setup attempt continues through observed enablement, child-mode selection and expected-build host verification. A source still missing at the activation deadline reports a discovery-stage failure with files retained; actual registration/enable API errors during replacement still fail transactionally. A registration/enable API failure restores previous bytes and attempts to restore the previous registration state, reporting both errors if restoration fails. A filesystem rollback failure retains the previous bundle at the reported recovery path. Remove first selects the existing ASCII-capable keyboard layout if Arion is selected, verifies the switch and disables the source; only then does it delete the bundle. Subsequent dictation selects external-editor delivery from the actual input source. A failed removal preserves the installed source state. Bundle copying runs off the UI thread; TIS registration, enablement and queries execute on the main thread under the SDK contract. Installation shows immediate progress and competing actions disabled; completion publishes pending/ready/failure on the main thread. A valid installed bundle not yet discovered by TIS remains pending instead of re-exposing Install. Polling refreshes externally changed activation state and records bounded state transitions without retrying enablement. Development payloads fail preflight before any installed-file replacement. Runtime preflight does not pin a publisher or replace the packaging gate’s profile authorization/CMS checks. Bounded diagnostic events record installation start/result, settings-open result and removal without raw errors or paths.
- **IPC** is a per-user Unix domain socket at `~/Library/Application Support/Arion/ime.sock` (mode 0600; only the same user can connect), one JSON object per line (bounded to 1 MiB). The IME sends startup `hello` (with its cached executable SHA-256), `activate` (with the client bundle ID and a fresh activation ID), `deactivate`, session-scoped `escape`, `committed` and `dictate` (the input menu's Voice input item, which toggles dictation as the tray item does; [IME-06](../../specs/007-ime-ranking.md)); Arion sends `begin`, `mark`, `commit` and `cancel`. Every write is bound to the activation and session; marks also carry a strictly increasing revision. Replaced connections cannot alter the current session. Normal app quit closes the socket and clears the draft. A macOS advisory lock serializes listener ownership and is released by the OS on process exit. Startup reclaims only a socket that refuses connections, after checking that its filesystem identity is unchanged; live sockets, unrelated files and symlinks are retained. A connection must send a valid hello/activation before replacing a client, so a liveness probe cannot revoke composition. The host sends a `hello` containing the SHA-256 of its executable, cached at startup, and reconnects even without an editable client. Update completion requires that expected executable identity on the new connection.
- **Pacing:** each accepted `mark` revision is typed into the marked text by a spring-paced typewriter (`composition.m`, after Doubao's `ASRTypeWriter`/`TypewriterSpring`; [research](../research/voice-typewriter.md)): characters already shown follow each revision in place (the marked text never retreats; a shorter draft cuts it at once), only new characters are typed, and the pace rises with the backlog. Commit, cancellation, empty drafts and invalidation are never paced: the final text replaces whatever is shown, exactly and at once.
- **Ownership:** in `system_ime` mode the coordinator captures an IME target only while the source is active, mirrors every accepted draft revision into the owned marked text, commits the reviewed text once through `insertText` and waits for the IME's acknowledgement (`applied`, otherwise `unknown`). Cancellation, failure, Escape, ordinary user key edits, deactivation, disconnect and the host's `commitComposition` clear the owned marked text and invalidate the session; an unconfirmed draft is never committed implicitly (IME-03).

The build prepares the nested input-method app under a temporary sibling and publishes only the completed bundle by same-filesystem rename. Localized `InfoPlist.strings` includes the full child-mode ID so TIS resolves the product name. The visible destination never exposes an executable still being linked.

## Consequences

Voice dictation requires the menu-bar app. ADR 017 adds a standalone local keyboard runtime to the IMK host. The updated app and host must be deployed together. Rebuilding or updating the app does not touch the installed copy in `~/Library/Input Methods`: when the installed executable, `Info.plist` or signature resource list differs from the bundled one, Settings › Keyboard offers **Update**, which stages and validates the complete replacement before switching away, requests the old host to quit, and verifies exit (with bounded forced termination if necessary) before promoting new bytes. It registers/enables the replacement, restores Arion only if it was previously selected, explicitly launches the host without activating it, and waits for the matching build handshake. A failed activation stops the failed new host before restoring previous bytes, registration and selection. A host that cannot be stopped leaves both builds at the reported recovery paths rather than replacing files under a live process. First-install consent can still leave a retained pending source; that state is not reported as a connected host. Transport race tests and an actual AppKit text-store harness verify ownership and Unicode behavior; they do not establish system input-source acceptance ([alignment report](../research/imk-typing-alignment.md)). Secure fields disable input methods system-wide, so no context can be read there. The speech recognizer still exposes no alternatives; the keyboard engine supplies its own lexical candidates independently of ASR and the optional RNK learned ranker. Windows TSF remains a separate task; on Windows input-method setup is unavailable until TSF exists; dictation uses the native external-editor route.

## Alternatives considered

Running recognition inside the IME process (duplicate model residency, two recognizer lifecycles) and XPC services (needs signed, sandbox-aware bundles not available to ad hoc development builds).


## Explicit activation continuation

First installation continues into a cancellable 30-second setup attempt. Installed-source retry and switching share `macos.ActivateIME`; neither replaces bytes. An owned distributed-notification observer is installed before requests and removed on exit; 250 ms bounded polling covers missed/coalesced notifications and command-line clients without a UI event loop. The worker queries actual state, requests enablement once, retries selection while bounded, and verifies the expected executable connection. UI TIS work runs on the main thread. A native cancellation token guards queued selection. Leaving setup or closing its window cancels continuation; ordinary state refresh never selects. Setup remains busy until the cancelled worker acknowledges exit. Errors carry discovery/enable/selection/connection stages, translated at the UI boundary. The per-user installation directory is unchanged; Apple documents both supported locations. Modern first-install consent behavior still requires actual-OS evidence; API success is not consent proof.


## Authenticated personal-vocabulary connection

[ADR 030](030-keyboard-vocabulary-transport.md) adds mutual audit-token and Developer ID publisher checks to macOS app/host IPC. Both endpoints require the expected peer identifier under their own validated publisher; ad-hoc builds cannot exchange private content. Vocabulary messages use a separately revisioned, capability-negotiated full snapshot and the existing encrypted native cache. Offline keyboard conversion remains independent of the app. Production authentication and dispatch are implemented; positive signed-pair and installed-host acceptance remain open.
