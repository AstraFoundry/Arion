## Build components

Use `make build <component>` with exactly one component per invocation:

| Command | Output |
| --- | --- |
| `make build desktop` | Native app and installer for the current host; configured ENV enables macOS signing/notarization and signed updates |
| `make build site` | Static marketing site in `apps/site/out` |

Both dispatch through `scripts/build.mjs`, also used by desktop CI. Missing, unsupported or extra components fail before building. Mobile and server builds are not registered yet. `make site-deploy` uses the same site build before deployment. The former `desktop-build` and `site-build` targets have been removed.

The foundation uses Node 24 and pinned pnpm 10.33.0 for workspace/check/driver tooling. `packages/core` declares Go 1.25.7 and `models` declares Go 1.25. The sync relay, updates service, and MyGo desktop declare Go 1.27.1. `go.work` and those modules select the patched `go1.27.3` toolchain for standard-library security fixes. Portable CI and native CI both install Go 1.27.3, and the service images build with that same toolchain. A newer toolchain still enforces each module's language version. Go automatic toolchain selection may download `go1.27.3` when a local `go` binary is older. Native shell compilation is distinct from functional speech/IME support.

For macOS development, use the [explicit release/development switch](local-dev.md#switch-between-the-release-and-development) and a persistent development signing identity.

The desktop shell does not need a database. Optional [clipboard history](../project/clipboard.md) uses its own bounded encrypted snapshot and OS-kept key. The marketing site builds from committed public configuration (`apps/site/.env.production`); only `make site-deploy` needs Cloudflare credentials, supplied by the shell running it. The sync relay has its own PostgreSQL, configuration and runbook under [deploy/sync](../../deploy/sync/README.md). Do not point it at another product's database.

Native CI invokes the Windows keyboard checks through `scripts/check-windows-keyboard-ci.ps1`. On macOS, `pnpm desktop:check` includes `pnpm keyboard:check` once before packaging. [GitHub-hosted Windows runners run as administrators](https://docs.github.com/en/actions/reference/runners/github-hosted-runners#administrative-privileges), so the Windows launcher creates a disposable standard user, loads its profile for DPAPI and runs the complete `check-windows-keyboard.mjs` suite with that identity. It restores workspace permissions and removes the account afterwards, refuses developer machines and persistent runners, and never weakens production integrity checks. Local Windows checks remain `pnpm keyboard:windows:check` from an ordinary desktop session. Both platforms include shared checks; Windows adds real conversion, module and owned-ACP tests, while macOS runs its native adapters. These isolated gates do not register an input source or replace installed-editor acceptance.

The credentialed Windows child receives the parent's resolved Go executable explicitly and prepends that SDK directory after its environment is created. It verifies the same actual SDK version reported by the parent and the PATH identity, records the executable hash in `windows-keyboard-ci/go-toolchain.json`, and uses `GOTOOLCHAIN=local`. Toolchain provisioning belongs to `actions/setup-go`; test execution must not pick an older machine SDK and download another compiler inside a bounded native gate. The `go` directive is a language/minimum-version requirement, not an exact SDK pin; the selected parent SDK can be a newer approved patch. The profile and active Go caches remain owned by the temporary test user; no release credentials are forwarded. The child copies only compiler and module cache data from `.workspace/ci-standard-user-go-cache` into its own `.workspace/windows-standard-user-go` directories and exports that data after successful checks. Copies preserve destination permissions, never profile ACLs. DPAPI, temporary files and private test reports stay in their existing isolated locations.

The hosted launcher grants only the temporary SID the required window-station/desktop access, then restores and reads back the original DACLs during cleanup. A native preflight verifies the expected SID, medium integrity, desktop, GUI creation, TSF and DPAPI before the suite. The child archives its private fixture reports into `.workspace/keyboard-evidence.zip` before account removal so the parent artifact upload can read them; the disposable VM reclaims the user profile. Hosted execution has verified this preflight, the complete Go desktop suite and cleanup under the temporary identity. Actual foreground activation and global key-hook E2E run separately in the runner's original interactive session; desktop access for the temporary user alone does not establish foreground-input ownership.

Native CI caches the ASR, LLM and keyboard dependency build trees and verified runtime downloads. `scripts/native-ci-cache-key.mjs` keys them by native source, pins, build scripts, patches, platform, architecture, `ImageOS`, selected compiler, SDK, and build settings. The absolute checkout path and the full runner `ImageVersion` are not part of the key. Compiler and SDK versions still change the key when the toolchain changes. `actions/cache` `restore-keys` reuse the newest cache with the same toolchain scope when source inputs change. Staging reconfigures those trees and checks pinned digests. Only a successful push to `main` saves the native dependency cache and the standard-user Go cache. Pull requests restore them, including by `restore-keys` prefix, and do not write them. GitHub does not let `main` read a cache written by a pull request. Each restore prints a `ci-cache` line: `exact-hit`, `no-exact-hit`, or `disabled`. `no-exact-hit` is a prefix restore when the action log says `Cache hit for restore-key`, and a cold start when it says `Cache not found`. Portable CI also restores the Go module and build cache from `go.work.sum` and the module `go.sum` files, and it restores the pinned actionlint tool. CMake builds use the host's available parallelism, capped by `ARION_BUILD_JOBS` or `ARION_KEYBOARD_BUILD_JOBS` when those are set. They do not pin a job count above the machine. Keyboard compile scripts reuse MinGW and Clang outputs from `.workspace/windows-compile-cache` when the compiler, flags, sources, and local headers match. That directory is part of the native cache. A quoted include that cannot be read is compiled again and is not stored. The standard-user session still runs every keyboard check and `go test -count=1`. Runtime staging, integrity checks, both Windows CPU variants, native tests, and main/release package verification still run. Desktop Go tests use `-count=1`, so cached compilation never substitutes for executing the suite. The standard-user Go cache has a separate key and the same restore scope. That key also includes the Go SDK and Go/native source inputs.

CI installs with a frozen pnpm lockfile. Checkouts are blobless and keep full commit history (`filter: blob:none`, `fetch-depth: 0`). Commits and trees in this repository are about 3.4 MiB. Blobs are about 1.1 GiB uncompressed and the full pack is 261 MiB. The current tree is about 68 MiB. A name-only diff uses `--no-renames`, so it does not download historical blobs. `make updater-check` / `pnpm updater:check` verifies the maintained MyGo update-channel patch. Portable CI runs the shared updater checks. A separate Windows job runs the same command, including `TestWindowsInstaller`, in parallel with the keyboard suite. The portable job also runs `pnpm site:check` (site dictionaries, types, lint, tests and static export). Pull requests run the portable job and the macOS and Windows native jobs, including the short native window E2E. A pull request that changes only `apps/site/`, `docs/`, or a root `README.md`, `README.zh-CN.md`, or `README.ja.md` skips the native jobs and the Windows updater job. Any other path, including desktop, IME, Go, scripts, and workflow files, runs them. The `required-checks` job fails the workflow when portable did not succeed, when a pull request's scope output is missing, or when a required native or Windows updater job did not succeed. A documentation-only decision is checked again from the diff. Pull requests do not run `node scripts/build.mjs desktop`, release collection, or the `desktop-*` artifact upload. A failed portable job cancels that direct CI run so Mac and Windows jobs do not continue. A newer commit on the same pull request cancels the older run. Pushes to `main` do not cancel an in-progress run. Main pushes package unsigned installers and upload `desktop-*` artifacts. Tagged releases and the signed macOS workflow call this same workflow with `release: true`. They keep their own concurrency groups with `cancel-in-progress: false`, and they package signed installers when their secrets are present. Tagged releases require Apple signing/notarization and update credentials and upload only a complete verified set for their selected platforms (all tags, including alpha: macOS ARM64 and Windows x64). Run studies and archive checks locally in the private [evaluation repository](https://github.com/AstraFoundry/Arion-evaluation), with a reviewed local driver and licensed corpus. GitHub Actions is disabled there. Keep raw traces private and follow the [repository split](../project/repository-split.md) for version binding.

Update and notification workflows are documented in [update lifecycle](../project/update-lifecycle.md). `make updater-e2e` uses owned temporary application bundles; `make notifications-check` checks native transport/registration code and `make notifications-prepare` builds a separate consent probe.

The desktop resource stage also builds the local keyboard ranker with Rust/Cargo and its checked-in lockfile. Install the native Rust toolchain before running resource preparation; `node scripts/stage-keyboard-ranker.mjs` builds the worker and collects all dependency licenses. The small model ships in the bundle; only the larger LLM remains a separate explicit download ([ADR 036](../decisions/036-two-stage-keyboard-ranking.md)).
