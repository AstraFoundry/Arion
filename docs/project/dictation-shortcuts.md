# Dictation shortcuts

Settings › Dictation and onboarding share a native keyboard recorder. The field shows only its current shortcut and a pencil icon. Clicking the pencil gives the field focus, turns it blue, displays **Press a new shortcut** and replaces the pencil with a cancel icon. Press and release a single supported key or a modifier combination to save automatically; there is no dropdown or separate Save action. English and Simplified Chinese use the same persisted identifiers. Modifier names follow the device: the internal `alt`/`super` identifiers display as Option/Command on macOS and Alt/Win on Windows, including settings, menu-bar/tray keycaps and dictation/translation hints.

Activation is replaced with native recording while the field owns focus. A recording publishes only after every constituent is released, preventing a held trigger's repeat from starting dictation when normal listening resumes. Escape, the cancel icon, losing focus, navigation and window close discard capture and restore activation. Retired callbacks cannot change the new listener. Unsupported unmodified typing is rejected while recording remains available for another attempt. Single modifier keys retain their left/right identity; combinations use modifier families.

Voice translation has an independent enable switch. Off shows only the switch. The shortcut and target-language controls reveal and collapse together below it using the shared 200 ms disclosure; the dictation card and translation switch stay fixed. Closing retains the visible shortcut until the animation finishes and disables its controls; rapid toggles reverse from the current height, and Reduce Motion applies the final layout immediately. Turning it on restores the previous shortcut if it is still available, otherwise chooses a nonconflicting supported key without changing dictation. The target language and previous assignment survive restart. Onboarding's translation-key step uses the same switch and recorder.

Global dictation and translation keys use current-caret external delivery even when the Arion input method is selected. With no editable input target, the final processed result stays on the clipboard. See [DSK-01/06](../../specs/001-desktop-input.md) and [ADR 033](../decisions/033-voice-shortcut-delivery.md).

## Choices and gestures

- macOS: Fn, left/right Option, Command, Ctrl and Shift, and F1–F20.
- Windows: left/right Alt, Ctrl and Shift, Menu, and F1–F24. Windows does not expose laptop Fn to the OS.
- Custom: any combination of Ctrl, Alt, Shift and Command (macOS) / Win (Windows), followed by a letter, digit, punctuation key, Space, Enter, Tab, Backspace, Delete, Home, End, Page Up/Down, arrow or function key. Text/navigation keys require at least one modifier; function keys can be used alone.

Press the modifiers before the trigger. Either modifier side satisfies a combination, and additional modifiers prevent activation. A hold of at least 300 ms ends when the trigger or a required modifier is released. A shorter tap continues until the next activation. Another key pressed during a hold cancels the session. Auto-repeat cannot start another session. Changing either assignment cancels current dictation before replacing the listener; queued events from the previous listener are rejected.

The listeners observe events and preserve system/application shortcuts. Settings do not infer conflicts from a nondefault assignment or claim to inspect other applications. Neutral guidance appears below the edited setting during recording. Information tooltips explain only the setting's behavior on hover or keyboard focus; they do not repeat recording guidance. Saving or canceling removes recording guidance. Duplicate errors identify whether the existing assignment belongs to dictation or translation, replace generic guidance, and remain below the edited setting for retry. Fn-specific setup notes stay with the setting using Fn; translation notes collapse with its controls. Shared permission/listener failures appear outside both shortcut cards, with Allow or Retry actions; retry changes neither assignment nor target language. Arion does not claim to detect or reserve shortcuts owned by other applications. On macOS, function-key availability depends on the keyboard's function/media-key settings. Letter and punctuation shortcuts use macOS US physical key positions and Windows virtual/OEM keys; other keyboard layouts can print different legends. Onboarding uses its general key illustration for combinations and keys absent from its laptop figure.

## Conflicts and storage

`Preferences.HoldKey` and `TranslateKey` retain their string fields. `TranslateKey=off` remains the enabled-state authority, and `PreviousTranslateKey` preserves a disabled assignment. Single keys retain identifiers such as `right_option`; combinations use canonical modifier order, for example `ctrl+shift+space`. Invalid or platform-unsupported dictation assignments are reported as repairs and normalized to the platform default. Existing valid single-key settings stay unchanged. The retired `shortcut` accelerator field is still ignored; it cannot overwrite a user's current hold-key assignment.

Only identical enabled assignments conflict. A standalone modifier and a combination using it (Right Command and Command+1, or Right Ctrl and Ctrl+Space) can coexist. Both settings recorders and onboarding reject a conflicting assignment with an inline message and remain ready for another attempt. Rejection preserves both assignments, translation enablement and its remembered shortcut. Application selection also refuses conflicts without replacing the listener. Normalization still disables conflicting translation when repairing stored preferences. Combinations with distinct triggers can share modifiers. When a configured single modifier prefixes the other shortcut, activation is deferred: a complete chord wins immediately; a standalone tap toggles on release; a standalone hold starts after the existing 300 ms threshold and stops on release. An unrelated key cancels the pending single-key action. A chord entered after the threshold cancels the provisional solo session without committing it, then starts the chord action when the coordinator is ready. Releasing either constituent ends a chord once; releasing its remaining keys never triggers the single modifier. Pending activation is invalidated by listener replacement, recording, consent revocation, sleep and lock.

## History

- `08c5227c` introduced the persisted `Shortcut` accelerator.
- `585488d8` added native hold-to-talk alongside the accelerator and its free-form recorder.
- `8957444e` removed the accelerator, recorder and `Shortcut` preference, retaining only three macOS and two Windows single-key choices.
- Custom combinations now use the native key-down/key-up path and the existing hold/tap gesture, instead of restoring a separate accelerator toggle.

## Verification

DSK-02 / DSK-A10 cover these choices. Portable tests cover canonical storage, identical-assignment rejection, modifier-prefix coexistence, every offered native mapping, extra modifiers, auto-repeat, release order, function keys and Windows AltGr. Prefix tests exercise both registration orders and release orders, tap/hold resolution, late chord takeover, the actual threshold timer/main-thread dispatch, and stale timer rejection after cancellation or listener replacement. Native macOS tests verify the event-tap mask includes key-up and retain consent/thread-lifecycle checks. Headless English/Chinese light/dark recorder tests verify focus, automatic save, conflict retry, cancellation and blur; they do not establish physical keyboard acceptance.

`pnpm core:check`, `pnpm desktop:check` and `pnpm i18n:check` are the normal gates. On Windows, `pnpm e2e:native` includes `TestWindowsCustomShortcutHook`: F8, Ctrl+F8 with either release order, immediate hook replacement, and recording through the production hook. `TestWindowsModifierPrefixChordHook` checks Right Ctrl pending → Ctrl+F8 activation → one release through the actual hook with either release order. Run it on the actual Windows interactive desktop. Cross-compilation and pure Windows event tests do not establish native Windows acceptance. Physical microphone-to-editor acceptance remains separate.

The implementation checks passed on macOS arm64: `pnpm core:check`, `pnpm desktop:check` (Go tests/vet, native hold-listener and keyboard regressions), `pnpm i18n:check`, `pnpm check`, and race checks for core application, shortcut interpretation and the custom editor. The Windows x64 adapter and shortcut UI test packages cross-compile and pass `go vet`; the new native Windows hook cases have not been executed on Windows. The IMK host source passes Objective-C syntax checking with the matching Xcode SDK. These checks do not replace physical-key or installed-package acceptance.
