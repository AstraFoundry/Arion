# Clipboard history

[010](../../specs/010-clipboard.md) defines P0; [ADR 034](../decisions/034-clipboard-history.md) records persistence and source isolation. Application ignore lists, folders, destructive management and separate full-preview pages are excluded by user request.

## Workflow

Settings → Clipboard exposes one opt-in collection switch. Its shortcut and maximum-count rows use the dictation disclosure and native key recorder. Disabled options are hidden; no separate pause preference exists. Exact dictation/translation/history shortcut conflicts are rejected. Recording temporarily suspends activation shortcuts.

The tray entry and configurable `CmdOrCtrl+Shift+V` shortcut open a frameless 270-DIP-wide picker beside the captured input. Height follows history content, between 100 and 198 DIPs, with at most four equal-height rows visible; additional records scroll. Prefer the caret rectangle when the OS exposes it; otherwise use the editable field frame. If input geometry is unavailable, use the mouse position and keep history accessible in copy-only mode. Placement flips above near the bottom and stays within the monitor work area. Opening history does not require an editable target or Accessibility permission. On macOS the picker is a nonactivating native panel with fullscreen auxiliary/Spaces participation; showing it must not activate Arion or switch away from the foreground application. Input availability remains a delivery concern. Clicking outside closes the picker.

Rows contain one-line text, compact file references or an inline image thumbnail, with a return icon on the right. File references use a small file icon and filename; a short extension appears as a separate uppercase tag instead of repeating it in the filename. Extensionless names remain intact. Multi-file groups retain their joined filenames and show a count tag. Full filenames remain in accessible labels and search. Only the hovered row shows its pin/unpin button. There are no timestamp labels, category tabs, full-preview page or footer copy/paste controls. Click a row, press Enter (including during search), or use its return icon to paste once into the captured external input after native focus/security checks. With an unlocated/unverifiable target, all three actions copy instead. The return icon tooltip follows the same target mode. Successful activation closes the picker. Up/Down select; Escape closes. The top-right search icon replaces the header title with an input; Escape first exits search. Delivery failure is visible in Clipboard settings and never retries the paste. Opening failure is not conflated with target/permission failure.

Resting the pointer on truncated/flattened text, a file name, or an image thumbnail for 450 ms opens a passive preview beside that content. Text preserves its original whitespace; file previews show complete paths; images scale to fit. Preview cards use Arion tokens in a nonactivating, click-through native flyout, can extend beyond the picker, and flip/clamp to the work area. Leaving the content, changing search/scroll targets, pasting or closing the picker dismisses it. Short previews size their height to the content. Cards are bounded at 320 × 220 DIPs (text at 12 lines); they have no controls or full-screen viewer. Only one larger image decode runs at a time, bounded to a 640-pixel edge, in memory; stale results cannot reopen a dismissed preview.

There is no delete/clear action, history management page or settings-management link. Automatic count/storage retention handles cleanup. Ordinary files remain references; folders and nonregular resources are excluded at capture, with mixed copies preserving ordinary-file order. Folder-containing legacy records are hidden and cannot be pasted. Refresh removes their pin protection so configured count/storage limits can evict them; source folders remain untouched. Missing files are disabled and checked again before delivery. Neither history retention nor UI actions modify source files.

Settings expose only the maximum ordinary-history count and preserve saved custom counts. [CLP-07](../../specs/010-clipboard.md#requirements) owns the presets, defaults and internal byte bounds. A new copy replaces the oldest unpinned record when the count limit is exceeded; records never expire because of age. Pins bypass the count limit but consume storage, and unpinning returns them to ordinary retention. Retention runs at startup, when opening history, and on captures, pins or limit changes; no periodic expiry job runs while idle or collection is off. Legacy `limits.days` preferences are ignored and disappear on the next settings save without resetting the count. See the [settings comparison](../research/clipboard-settings.md).

## Dictation and privacy

Input-target dictation keeps its existing ownership-checked system clipboard restoration and never enters clipboard history. A completed dictation may explicitly enter history only when its native adapter positively reports **no editable input**, the final text was successfully copied, and collection is enabled. Before starting a session, a positive native no-input observation selects the native copy route even when the Arion input source is selected; unknown capability keeps the selected IME route. An already-owned IME session never switches transport after failure. The `CommitResult.NoInput` fact propagates through the coordinator's final event. On macOS, a supported focused-element query returning `kAXErrorNoValue` is a positive absence observation; it must survive both the pre-session route check and commit-time capture. Unknown/unsupported/unresponsive focus queries remain uncertain. A generic `copied` outcome alone is insufficient: permission/provider uncertainty and target-change fallbacks must not be mistaken for absence of an input. Secure fields, cancellation and unsuccessful delivery never authorize recording. These explicit captures serialize after an in-flight mutation through a bounded pending history using the same count/byte rules.

All internal revisions still carry the native marker and remain excluded from clipboard polling. No text comparison is used; a later user copy of identical text remains eligible. The menu-bar panel no longer exposes the last dictation or separate original/final copy controls. Its ready height is 160 DIPs, adding space only for a visible scene card, model setup or update notice; scene choices scroll within the available space.

## Ownership and persistence

- `core/domain/clipboard.go`: payload identity, deduplication, ordering, filtering and retention.
- `core/application/clipboard*.go`: serialized capture/pin/retention and revision boundaries.
- `infrastructure/clipboardhistory`: authenticated snapshot validation.
- `infrastructure/encryptedfile`: shared AES-256-GCM/atomic ciphertext files.
- `infrastructure/clipboardos`: transfer mapping, internal marker, ordinary-file checks and target contract.
- `infrastructure/macos` / `windows`: native revisions, input geometry/identity/security and single-paste dispatch.
- `bootstrap/clipboard*.go`: collection, explicit dictation capture, key/shortcut/window lifecycle and bounded resource workers.
- `ui/features/clipboard`, `ui/pages/clipboard`: localized compact picker and collection settings.

One bounded snapshot lives at `<data directory>/clipboard.bin`. Content, image bytes, paths, timestamps and derived IDs stay inside ciphertext. `clipboard-key` is a distinct Keychain/DPAPI item. Its service follows the desktop profile: `Arion Dev` for development and `Arion` for releases, with no automatic key migration ([ADR 035](../decisions/035-development-runtime-isolation.md)). Missing-key/authentication/read failures cannot create replacement history. No plaintext image cache, account sync, diagnostic content, OCR or polishing-context source exists. Confidential/transient/generated markers are respected; this does not promise universal secret detection.

## Verification

Run `pnpm core:check`, `pnpm i18n:check`, `pnpm check` and `pnpm desktop:check`. On macOS use the selected Xcode SDK and documented `CC` wrapper. Native suites need owned localhost fixtures and independent named pasteboards. `ARION_UI_SNAPSHOTS=<directory>` saves headless renderings.

`TestClipboard*` covers retention/encryption/source boundaries, ordinary-file filtering, inline image rows, both locales, search and target-aware Enter/return-icon/row activation in paste and copy-only modes, file extension/count tags, hover-only pins, absence of destructive UI, four-row scrolling, delayed hover previews and original preview content, work-area placement, validation cancellation and explicit dictation capture eligibility/serialization. Coordinator tests verify propagation of the positive no-input fact. `TestNativeFocusAbsence` runs the shared native focus-query mapping against owned injected API outcomes, including NoValue, provider errors and secure-input refusal; it does not establish a particular external app’s AX behavior. `TestClipboardInForeignFullscreenSpace` exercises the production picker against an owned foreign fullscreen editor, checking active-Space membership, compositor ordering, keyboard focus, and close/reopen without activating Arion. `TestNativePasteboardTransaction` retains isolated snapshot/restore and intercepted dispatch; it never types into the user's foreground application.

Headless rendering, geometry tests and Windows cross-compilation do not establish actual target-app placement or host consumption. macOS and Windows input-provider compatibility, mixed-DPI placement, native permission prompts and external-editor paste require actual OS acceptance. The new Windows UI Automation metadata/identity adapter has not been executed on Windows here.
