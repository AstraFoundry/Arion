# Agent handoff

Clipboard P0 is defined in [010](../../specs/010-clipboard.md) and [ADR 034](../decisions/034-clipboard-history.md). Domain/application history, encrypted snapshots, native revision filtering, localized picker/settings, and tray/shortcut wiring are implemented. Application ignore lists are excluded. External-editor/file-manager paste, OS permission and Windows runtime acceptance remain target-OS checks; see the [clipboard workflow](clipboard.md).

Read [AGENTS.md](../../AGENTS.md), [architecture](architecture.md), [repository](repository.md), and the relevant [spec](../../specs/README.md) first. Claim a task in an ignored `.workspace/todo/` file, record touched paths, then report implementation, checks and remaining gaps. No dates or duration estimates.

## Implemented

- **TSF-01 (voice primitives):** x64 COM service, locked owned ranges, same-user/session/integrity-bound pipe, build/session/revision validation and acquisition acknowledgement before recording. Actual RichEdit and ACP-store checks cover Unicode commits, duplicate refusal, selected-text restoration, focus/selection invalidation and protected-field refusal; ACP additionally covers host refusal and deferred-lock cancellation. Windows Settings exposes explicit UAC installation/selection/status/removal. Global registration/UAC, installed speech and editor compatibility acceptance remain open; Pinyin/live replacement are unsupported. See [runbook](../operations/windows-input-method.md).

- **CORE-01:** session aggregate (monotonic revisions, exactly-once commit claim, terminal immutability), stable error codes, dictation coordinator with generations, bounded queues, cancellation, acoustic finalization, correction and single commit; mode routing for shortcut and system IME sessions. Race-tested (CTR-A01/A02/A04/A06, DSK-A02/A04/A06/A07, SPH-A01/A02/A04/A07, IME-A02/A03 at core level).
- **MAC-01:** microphone consent and capture (miniaudio/CoreAudio, 16 kHz mono, persisted software input gain, device loss as discontinuity), Accessibility consent, target capture with secure-field detection, one-route insertion ([ADR 003](../decisions/003-insertion-routes.md)), global dictation key (hold or tap) with Escape cancellation, sleep/lock cancellation.
- **ASR-01 / model provisioning:** native Qwen3-ASR 1.7B workers (`mlx-audio-swift` 8-bit on macOS Apple silicon and `speech.cpp` Q8_0 on Windows x64, [ADR 020](../decisions/020-native-qwen-asr.md)), pinned catalog with member digests, verified resumable downloads with atomic publish, explicit platform bundle adoption superseding automatic selection for native Qwen3-ASR ([ADR 004](../decisions/004-automatic-model-selection.md), [ADR 020](../decisions/020-native-qwen-asr.md)).
- **COR-01 (rules):** `arion-rules-v4` conservative corrections (spacing, recognizer casing, approved vocabulary), preserving quoted spelled letters and leaving repeated first-person I and standalone hesitation for polishing, keeping raw and corrected text separate.
- **LRW-01 (rewriting, macOS Apple silicon and Windows x64):** segment cuts at pauses stay, and the rewrite runs once after release on the full recognized text ([ADR 023](../decisions/023-final-only-polishing.md), [ADR 011](../decisions/011-live-local-rewriting.md), runtime in [ADR 018](../decisions/018-staged-gguf-rewriting.md) and [ADR 025](../decisions/025-windows-local-polishing.md)). Closed segments are not sent to the text model during speech, and no polished preview is shown. The original is kept. The shipped rewriter is Qwen3.5-2B Q4_K_M in an isolated `arion-llm` process that drives llama.cpp; selector then formatter, delivery-only validation, and no silent model fallback. Configuration is [local rewrite](../operations/local-rewrite.md). The earlier Qwen3 1.7B / `live-v2` ONNX gate remains historical evidence in [live-rewrite-v1](https://github.com/AstraFoundry/Arion-evaluation) (`benchmarks/results/live-rewrite-v1/README.md`); LRW-A06 (blind review) is open. Independent `speech-spans-v3` cleanup still precedes organization.
- **UI-01:** menu bar icon and popover panel, click-through overlay pill with spring motion, settings (permissions, dictation and translation shortcut recorders, automatic dictation delivery, microphone device, gain with suggested distances and meter, model, vocabulary, about with updates, local diagnostic ZIP export, privacy and project links), first-run onboarding with permission gates and model download; headless view tests and native window E2E; persisted English/Simplified Chinese interface language with live switching, typed catalogs and localized macOS permission resources ([i18n](../frontend/i18n.md), DSK-A09).
- **IMK-01:** `ArionInput.app` voice composition over scoped local IPC ([ADR 006](../decisions/006-macos-input-method-host.md)); staged install/rollback and checked removal. **KBD-01 (code):** offline full-Pinyin engine, native typing ownership/candidate-window wiring, standalone Shift switching with caret feedback (Shift+Space retained), direct punctuation and encrypted learning ([ADR 017](../decisions/017-offline-pinyin-keyboard.md)); The latest native arm64 and Rosetta x86_64 engine/AppKit runs each pass 36 cases, including standalone Shift, direct symbols and the caret badge lifecycle. Storage and final desktop/IME race checks pass. Intel macOS is outside future support and acceptance gates ([ADR 021](../decisions/021-apple-silicon-only-macos.md)). The macOS 26.6.2 signed/notarized source probe enables with status `0` but leaves its parent disabled and selects with `-50`; successful source activation, system IMK dispatch, external-editor dispatch and host quality/latency gates remain open. The strict Data Protection provider now has a matching validated Developer ID provisioning profile. A profile-authorized signed harness passes real learned-ranking restart, key deletion/loss rejection and cleanup with verified device-only/nonsynchronizing OS attributes. Real owned legacy-key rejection and strict-policy regressions pass; the 100-case engine development baseline records 71% exact intended commit ([report](https://github.com/AstraFoundry/Arion-evaluation) (`benchmarks/results/imk-quality-v1/README.md`)), without a parity claim.
- **MEM-01 (local):** approved vocabulary encrypted with AES-256-GCM, key in the Keychain/DPAPI ([ADR 005](../decisions/005-local-encryption.md)); no desktop outbox yet.
- **SYNC-01 / SYNC-08 / SYNC-09:** `services/sync` ciphertext relay with `noop` and `oidc` gates, device signatures, push/pull/snapshot/ack, revocation and `POST /v1/security-events` ([ADR 015](../decisions/015-hosted-relay-account-authorization.md)). MEM-A13–A16 are covered by unit tests against an in-memory port double and a local JWKS. `make sync-integration` is the PostgreSQL check and is not part of the default test run. Desktop enrollment remains open.
- **SYNC-10 (service):** desktop account sign-in ([account sign-in](account-signin.md)): RFC 8252 loopback, PKCE S256, refresh token in the OS credential store, a waitlist client that views do not call, and sign-out that keeps local keys and memory (MEM-A17). The onboarding account step, the settings sidebar account card and Settings › Account are built on it ([views](account-signin.md#views)). They show hosted sync only when the token carries the entitlement, and they have not been run in a native window on macOS or Windows. Native Keychain and Credential Manager behavior has not been executed on those operating systems.
- **MEM-02 (edit learning, macOS):** corrections of inserted text are learned on the device, shown with an undo, recalled by a one-pass index and, bounded, in the rewrite prompt ([ADR 014](../decisions/014-edit-learning.md), [edit-learning-v1](https://github.com/AstraFoundry/Arion-evaluation) (`benchmarks/results/edit-learning-v1/README.md`)). Windows does not read fields, so it does not learn yet.
- **EVAL-01 / DATA-01 (partial):** production-pipeline benchmark driver, corpus builder, model-comparison experiment and catalog recording; macOS product scenario driver with an owned editor fixture.
- **WIN-01 (code):** WASAPI capture through the same miniaudio adapter, guarded clipboard paste, DPAPI key storage. Windows SendInput inserts once at the caret focused at commit time. A caret move, a switch to another editable field, or an edit in the captured field still inserts at that caret. No editable focus leaves the text on the system clipboard with outcome `copied`. A secure field is refused and is not copied to the clipboard. Native CI has exercised window lifecycle, owned Notepad insertion and the hold-key hook; the complete packaged microphone/recognition path remains unverified ([validation](../quality/validation.md)).

Verification results and their limits are recorded in [validation](../quality/validation.md).

## Contextual keyboard completion

The macOS whole-input generation path is implemented under [ADR 038](../decisions/038-contextual-keyboard-completion.md). Local phonetic-constrained smoke and native engine/editor fixtures are separate checks; installed-editor context acquisition and broad unseen quality remain open. Windows generation is not implemented.

## Decisions needed at the appropriate task

- Ranking/correction checkpoints after measured gates; recognition bundles are selected by ADR 004.
- Recovery-secret enrollment stays rejected (`RECOVERY_UNSUPPORTED`) until a vetted format exists. Revocation rotates the key epoch; clients re-encrypt because the relay cannot read ciphertext.
- Local SQLite driver and encryption boundary before persistence migration code.
- Windows uses an x64 COM voice service and same-user pipe; remaining system/editor acceptance is in the [runbook](../operations/windows-input-method.md). The macOS IMK host and scoped local IPC are implemented; known-authorization activation/retry/cancel, cached-authorization reinstall and real editor typing pass on the local arm64 host ([run](https://github.com/AstraFoundry/Arion-evaluation) (`benchmarks/runs/ime-activation-v1/README.md`)); clean-account first-consent/denial acceptance remains open; Intel macOS is unsupported ([ADR 021](../decisions/021-apple-silicon-only-macos.md)).
- App identifier/signing identities, minimum OS/RAM and update trust before public packages. The controlled identifiers are `si.astrafoundry.arion` and `si.astrafoundry.inputmethod.arion`; signed input-source and host acceptance remain open.

These are bounded open decisions, not permission prompts for already-authorized research or reversible scaffolding. Continue independent work, use evidence, and ask only when a choice changes user-visible scope or trust.

## Handoff format

Task ID; changed paths; requirements/acceptance IDs satisfied; exact checks and OS/hardware; model/protocol revisions; observed behavior vs unverified claims; unresolved next dependency. Update docs and task status in the same implementation change. Do not mark a task complete on Linux-only tests when its gate requires macOS/Windows host behavior.

## Qwen experiment handoff

Read [the paper strategy review](../research/qwen-paper-strategies.md) for PAP-00–11 dependencies and source-paper limitations. These are unexecuted research branches: establish parity and reviewed acoustic/context baselines before task-specific training; ordinary prose memory and generic writing scores do not establish faithful correction.

Read [the measured CPU report](https://github.com/AstraFoundry/Arion-evaluation) (`benchmarks/results/qwen-pipeline-diagnostic-v1/README.md`) before selecting a rewrite checkpoint. These unreviewed development results favor single-pass intent cleanup with fixed-prefix prefill during capture for further work; they do not approve a product model or establish Typeless parity. Preserve the optional native runtime decision and strict rewrite/E2E gates. Evaluate typed approved vocabulary through existing `domain.Correct` and ASR vocabulary bias separately; free-form memory/context prompting did not pass its dedicated development cases. Python workers are benchmark adapters and must not become the packaged desktop runtime by implication.
