# Automated end-to-end tests

## Implemented native lifecycle

`make e2e` / `pnpm e2e:native` runs build-tagged Go tests in an actual macOS/Windows desktop session. The test hosts the production composition root (`bootstrap.App`) in an isolated temporary profile on MyGo's native loop.

DSK-A09 also switches language through the production preference action with settings/onboarding already open, checks native titles in both directions and captures Chinese Content.

`TestOnboardingCompletionOpensSettings` covers the DSK-A15 completion transition through the production action: onboarding closes, Settings is visible and focused, and completion is saved in the isolated profile. This test does not relaunch the process.

Checks: the click-through overlay exists, stays unfocused and draws an explicit failure when dictation starts in a fresh profile (PERMISSION_DENIED with the capability named when Accessibility is not granted, otherwise MODEL_MISSING); settings and onboarding windows show native Content, render nonblank captures, resize, close once and release their views. On Windows the tests also type Unicode text (including CJK) into an owned Notepad through the production `SendInput` route and check that a focus change before commit inserts nothing. Go test binaries carry no manifest, so the Windows runner compiles the test executable and places [`e2e/windows.manifest`](../../apps/desktop/e2e/windows.manifest) beside it; it mirrors the manifest `mygo build` embeds (Windows 8+ compatibility for the hidden-title-bar controls, per-monitor DPI awareness, UTF-8). A missing OS/session is a failure, not a success-shaped skip. Ordinary `pnpm test` excludes interactive tests; CI native jobs explicitly run them.

`TestOverlayInForeignFullscreenSpace` (DSK-A13, macOS) compiles and launches the owned AppKit editor fixture as a separate application, focuses Editor A and enters native fullscreen. Starting a production session in the isolated profile shows the actual failure overlay. The test checks `isOnActiveSpace` and the on-screen window-server list: the overlay overlaps and is ordered above the editor, while the editor's PID stays frontmost and its text view keeps focus. These observations catch windows whose `IsVisible()` is true in a different Space. Content PNG and compositor metadata are saved under `.workspace/e2e/darwin/`; no Screen Recording or Accessibility grant is needed for these checks. Cleanup exits the fixture's fullscreen Space and terminates only that owned process.

`TestCaptureReadsWebSite` (SCN-A04, macOS) is opt-in: with `ARION_E2E_SITE=1` and Accessibility granted to the process running the tests, it serves a local page with an autofocused text area, opens it in Safari and, when installed, Chrome, and requires the production target adapter to report a text field on host `127.0.0.1`, and no host once scene selection is off. Without the grant it fails rather than skipping. The browser windows it opens stay open.

`TestReadContextFromWindow` (CTX-A04, macOS) is opt-in the same way: with `ARION_E2E_CONTEXT=1`, and Accessibility and Screen Recording granted to the process running the tests, it opens a local page in Safari whose text area has text before the cursor, and requires `ReadContext` to return that text and the window's recognized heading, and nothing with its gates closed. Capture and recognition times are logged.

`TestLearnFromEditInOwnedEditor` (MEM-A09/A11, macOS) is opt-in with `ARION_E2E_LEARNING=1` and Accessibility granted to the test runner. In the owned AppKit editor fixture it inserts through the production target adapter, keeps following the field, has the fixture retype `jason` as `Jayson` through the text system, and requires the edit tracker to learn exactly that pair and release the field; a secure field must not be followed. The fixture's `replace` command exists for this test.

## Guarded macOS system paste

Run `make e2e-paste` or `pnpm e2e:paste` in an interactive macOS session with existing Accessibility access for the test process. Missing access fails explicitly; the test never grants permissions or changes input sources. Chrome coverage is skipped explicitly only if Chrome is absent.

`TestGuardedSystemPaste` exercises the production target capture/commit adapter, real Command-V dispatch, and observed text/input counts in a separate owned AppKit/WebKit fixture. It checks exact CJK/emoji/combining-mark/multiline selection replacement, duplicate rejection, focus and selected-range changes, cancellation, stale session identity, secure fields and clipboard restoration. An installed Chrome is launched with a temporary isolated profile against a local page; both textarea and contenteditable must receive exactly one input event with the expected text. Only the owned Chrome instance and fixture are terminated. Original clipboard items are saved and restored only while the fixture still owns the test value; newer user clipboard data is preserved. The fixture has a standard Edit/Paste menu so Command-V follows actual AppKit key-equivalent dispatch.

Separate race-enabled adapter/coordinator tests inject pre/post-stage cancellation, post-send cancellation, blocked queue cancellation, competing transactions, unavailable clipboard and restore failure. Native transaction tests use real named pasteboards with multiple items/binary types and intercepted CGEvent delivery to check clipboard races, empty-board restoration and last-moment focus/range/secure refusal. These injected cases are not host E2E evidence. IMK composition regressions remain separate below. The paste E2E directly commits synthetic text and does not exercise microphone/recognition, actual Lark/Codex editors, office/terminal paste behavior or Windows.

## Diagnostic export (DSK-A14)

`TestDiagnosticExportNativeDialog` is opt-in with `ARION_E2E_DIAGNOSTICS=1` and `ARION_E2E_DIAGNOSTICS_EXPORT` pointing to a nonexistent ZIP in an isolated output directory. A UI driver answers two actual save sheets: cancel the first, then choose that directory/filename and save the second. The test requires idle after cancellation, saved after export, and both a manifest and JSONL files in the ZIP. It never sends the archive anywhere. Native shell tests use an offline temporary profile and remove it on normal exit.

The macOS arm64 native save/cancel flow passed with an isolated `.app` harness and Computer Use; Finder selected the saved ZIP. Private evidence is in `.workspace/e2e/diagnostics-native/`. Windows native save/reveal remains unverified.

## Headless view tests

`go test ./ui/app` renders every surface with MyGo's `ui.Tester` (no window): overlay phases (the dictation pill typing out its draft rather than showing it at once) and outcome timeouts, the menu bar panel (start, live, copy, no model card when ready, download progress, failed download retry fitting under four lines of dictation), each settings section including the dictation key picker and its Input Monitoring notice, the Keyboard section (input-source states, page size, candidate size, context ranking; hidden where the system has no input method) and the Dictation pointer to it, vocabulary entry and insertion method, and the complete onboarding flow with its permission gates, Accessibility auto-advance, optional input-method installation/deferral and selection gate, the dictation key step (waits for Input Monitoring, acknowledges a real key press), the shared keyboard settings guide without a drag tile, compact Microphone/Screen Recording switch guides in both languages, and the sync step (continue locally, browser wait and cancel, sign-in failure, waitlist, entitlement), Settings › Account in each sign-in, waitlist and revoke-failure state, the macOS consent guide card (English, Simplified Chinese, close action), plus the panel, settings, onboarding and guide in the dark appearance. The guide's drop into System Settings has no automated check: it needs a packaged app and a person (DSK-A11), and tests must not change the real consent database. English/Simplified Chinese tests cover the real picker, all settings sections, panel/overlay copy and download formatting; switching languages preserves user text and retranslates existing form errors. `ARION_UI_SNAPSHOTS=<dir>` saves PNG frames for review.

MyGo `CapturePage()` renders Content; it does not verify the OS compositor, GPU pixels, accessibility tree, text injection, microphone or IME. Captures are saved under ignored `.workspace/e2e/<platform>/`. These checks establish native shell lifecycle only.

## Dictation listener regression checks

On macOS, `pnpm desktop:check` also runs `node scripts/test-macos-hold.mjs`. It compiles the production native listener against a controlled Core Graphics boundary and real CFRunLoop/pthread lifecycle. It checks denied consent before tap creation, null/disabled taps, 100 immediate start/stop cycles, raw callback delivery, timeout re-enable and revocation/recovery. It never requests or changes system consent. Bootstrap tests cover visible registration failure, automatic restart after consent, revocation and rejection of events queued by a retired listener. These automated checks do not establish physical Right Option delivery or a real OS permission-grant flow. ## IMK composition regression checks

Typing regressions replay duplicate down/down/up/up modifier delivery captured in Codex/Cursor, require exactly one toggle, and ensure duplicates cannot extend the deadline or restore a chord-cancelled tap. They also include missing IMK modifier keycodes `0` and `255`, known/anonymous press-release pairing, ambiguous modifier changes, Shift chords, long holds and cancellation. These constructed events exercise the production typing owner; actual host dispatch remains a separate acceptance scenario.

On macOS, `pnpm desktop:check` runs `pnpm keyboard:check`, which stages the pinned public runtime/SDK and includes `node scripts/test-input-method.mjs`: production native composition state against an actual AppKit text store through a protocol adapter, including stale activation/session/revision rejection, cancellation, user edits, duplicate commit, emoji/CJK UTF-16 boundaries, and paced drafts (typed out in steps, revised in place without retreating, cut at once by a shorter draft, replaced exactly by commit and stopped by commit or cancel). The portable `infrastructure/imebridge` tests cover local IPC ownership, acknowledgements and disconnects; use `go test -race ./infrastructure/imebridge` from `apps/desktop` for concurrency checks. The macOS installer tests use temporary bundle trees and injected registration callbacks to verify staging, rollback/recovery, executable/symlink preservation and refusal to delete after a disable error; bootstrap tests preserve the selected mode on failed removal. These are transport/text-system/filesystem regressions, not real IMK input-source registration, selection or keyboard dispatch. The [alignment report](../research/imk-typing-alignment.md) records remaining source/typing acceptance gates.

`node scripts/test-keyboard-learning.mjs` uses the real C++ storage adapter/CryptoKit implementation with injected synthetic keys and temporary files: ciphertext-only persistence, transaction abort/commit, wrong/missing key, tamper, reset, encrypted backup/restore, locking and I/O failure. `node scripts/test-keyboard-input.mjs` runs the actual pinned engine/schema and production typing owner against AppKit, including paging, partial selection/rollback, editing, Chinese/English switching, stale callbacks, data-integrity rejection and a real learning-write failure that must not swallow an engine commit. The latest native arm64 and Rosetta x86_64 engine/AppKit runs each pass 36 cases, including standalone and anonymous Shift events, chords, long holds, cancellation and the language badge lifecycle. Physical Intel remains untested. The candidate bar's drawing is not covered by these tests. These tests use synthetic learning keys and never access the user's Keychain or alter their input sources. Test reports retain the engine/text-system boundary; actual IMK event-dispatch and external-editor evidence remain separate. A profile-authorized real-Keychain harness independently passes six lifecycle phases with verified OS policy attributes and restores both stores; that harness does not dispatch IMK events.

## Product scenario suite (all platforms)

[16 executable scenarios](../../tests/e2e/desktop-scenarios.json) define actions and observable assertions for shortcut/offline exact-once insertion, cancellation/stale callbacks, focus changes, secure context, denied microphone, IME registration/lifecycle/Unicode/user edits, candidate selection, uncertain commit, encrypted relay conflicts, tampering/revocation/tombstones and offline outbox restart.

Run `make e2e-scenarios DRIVER=... OUT=...` after implementing the OS driver. The [JSONL contract](../../tools/evaluation/README.md) uses actual application/native host binaries and isolated fixtures. The suite withholds expected assertions from the driver. Each result needs live observations, `fixtureOwnership:"isolated"` and nonempty `evidence:[{path,sha256}]` files; the harness verifies hashes and values, not a driver `passed` flag. Artifact checks are required before launch.

The harness requests `cleanup` on success/failure and requires confirmation before a passing report; drivers also handle parent exit/signals. Reset only owned fixtures between scenarios and restore owned network fault injection afterwards, including on failure. Use dedicated test profiles/VMs for microphone denial and IME installation; do not alter a user's real permission database or installed input sources. Editors must report their real text, host selection/range, composition and insertion counts. Network assertions use process-scoped controlled observation. Relay fixtures expose actual ciphertext database/log snapshots; mock persistence cannot fulfill sync acceptance.

Capabilities missing from the hello handshake fail explicitly. Current shell implements none of these product adapters, so this suite has not passed. A synthetic transport unit test checks the harness only. The native-shell test remains independently runnable.

## Input-source setup states

IME-A01 checks installation progress, then distinguishes pending system setup, ready and active. A register/enable success code with a still-disabled source must retain the registered bundle, preserve the native authorization flow and offer explicit Keyboard settings navigation with adding/allowing instructions. Closing settings must leave a reopen action. Verify the row refreshes after the user changes the OS source list, without an app restart. Copy/register/enable API failures must roll back and preserve retry plus content-free diagnostics. A failed settings-open operation keeps the pending source and offers explicit navigation instructions. The controller/view/temporary-filesystem tests exercise these states in isolation; actual enabled-source observation, consent and typing require the authorized native OS scenario.

For the post-consent path, verify that a native Allow prompt is not displaced by automatic settings navigation. Installed bytes absent from TIS must remain pending and must not trigger another payload replacement. An ad hoc/unsigned payload must fail preflight before touching a previously installed host. Complete the real scenario from the signed release app; an Arion Dev requester is separate evidence. Runtime preflight can be checked read-only with `ARION_TEST_IME_PAYLOAD=/absolute/ArionInput.app go test ./infrastructure/macos -run TestInputBundleConfiguredDeveloperIDPayload -count=1` from `apps/desktop`; this validates the actual signed artifact without registration or host launch.

Dictation routing is automatic in the product. The E2E-only `set-mode` command injects a route and cancels the old generation for ownership fault scenarios; it never writes a user preference. Core tests cover per-session selection, fixed-route commits and IME-only cancellation. Settings tests cover hidden route/transport controls in both interface languages on macOS and Windows; these do not establish real OS input-source acceptance.

IME upgrade checks cover old-host exit before promotion, stop-failure preservation, failed-build rollback ordering and recovery-file retention. Transport race tests cover orphaned/live/symlink paths, non-disruptive liveness probes, build-bound readiness, disconnected hosts and updates blocking new owned capture. The native host also connects without an editable field, allowing upgrade readiness to be verified from Settings without capturing user text.
