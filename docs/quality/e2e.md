# Automated end-to-end tests

## Implemented native lifecycle

`make e2e` / `pnpm e2e:native` runs build-tagged Go tests in an actual macOS/Windows desktop session. The test hosts the production composition root (`bootstrap.App`) in an isolated temporary profile on MyGo's native loop.

DSK-A09 also switches language through the production preference action with settings/onboarding already open, checks native titles in both directions and captures Chinese Content.

`TestOnboardingCompletionOpensSettings` covers the DSK-A15 completion transition through the production action: onboarding closes, Settings is visible and focused, and completion is saved in the isolated profile. This test does not relaunch the process. `TestSettingsLaunch` covers which later starts open Settings: a user-opened process, including an update restart, does; a login-item start, an unfinished onboarding, a notification-owned launch and a scripted session do not. A Spotlight-style reopen of the running app is the production `OnActivate` / `OnSecondInstance` path and is not a separate process launch in this suite.

Checks: the click-through overlay exists, stays unfocused and draws an explicit failure when dictation starts in a fresh profile (PERMISSION_DENIED with the capability named when Accessibility is not granted, otherwise MODEL_MISSING); settings and onboarding windows show native Content, render nonblank captures, resize, close once and release their views. On Windows the tests type CJK, emoji and combining marks into an owned standard Win32 editor through production `SendInput`, observe real `WM_CHAR` delivery, reject duplicate tokens, and check focus/selection changes, stale generation, cancellation and password refusal. Cancellation during delivery stops subsequent batches and retains `unknown` for already posted input. The fixture owns its native windows and message threads; it does not depend on the installed Notepad version or touch existing documents. `TestWindowsContextFromOwnedWindow` exercises real UI Automation against visible synthetic text, checks the source switch and password exclusion, and refuses password/unknown focused controls. Windows context currently establishes field safety only for standard `EDIT` controls; other controls have no context read until a verified safety adapter exists. The PowerShell reader explicitly initializes Microsoft's installed legacy-control providers before traversal; an initialization failure returns no content. These adapter tests commit synthetic text directly and do not establish microphone/ASR or TSF acceptance. Go test binaries carry no manifest, so the Windows runner compiles the test executable and places [`e2e/windows.manifest`](../../apps/desktop/e2e/windows.manifest) beside it; it mirrors the manifest `mygo build` embeds (Windows 8+ compatibility for the hidden-title-bar controls, per-monitor DPI awareness, UTF-8). A missing OS/session is a failure, not a success-shaped skip. Ordinary `pnpm test` excludes interactive tests; CI native jobs explicitly run them.

`TestWindowsMicrophoneLifecycle` is opt-in with `ARION_E2E_MICROPHONE=1`: the production microphone adapter opens the actual default capture endpoint for two one-second cycles, checks 16 kHz mono frames with matching session identity and monotonic sequence/sample offsets, stops without late callbacks, and reopens. It retains counters only. The local Windows run found two capture endpoints and received 49 frames / 15,680 samples in each cycle; both stops and reopening passed. Execute outside the restricted process sandbox in the interactive Windows session. Device denial, unplug/suspend and recognition quality remain separate acceptance cases.

Windows UI Automation initializes its owned PowerShell process and Microsoft providers within a separate 15 s startup bound. Before READY it also JIT-compiles the traversal and connects the UI Automation client without inspecting the target. The child sends READY and waits for GO before resolving the captured window; the parent revalidates the target and starts the unchanged 1.5 s traversal deadline before GO. Cancellation remains active in both phases, and every failure discards output and reaps the child. `infrastructure/windows` subprocess tests cover slow startup, both phase deadlines and cancellations, malformed readiness, missing/failed/oversized output, and authorization cancellation/expiry before GO. The real owned-window E2E logs total capture milliseconds without logging its text. The final rewrite's independent 1.5 s context wait is unchanged. A prior Windows CI run exhausted the old combined deadline at 1.55 s; passing protocol fixtures alone do not establish that the actual CI UIA read now completes.

`TestContextReaderInitializesBeforeAuthorization` logs static assembly-loading, provider-registration and reader-compilation phase names with elapsed milliseconds. It runs the real initialization script against an unauthorized synthetic handle and retains stderr even when startup fails; no target text is read. These observations distinguish cold initialization failures from traversal failures without changing either deadline. Run `go test -v ./infrastructure/windows` from `apps/desktop` on Windows.

The isolated reader explicitly starts PowerShell with `-Mta` and checks the actual apartment before loading UIA. Windows PowerShell otherwise defaults to STA; [Microsoft's UIA threading guidance](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-threading) recommends a non-UI MTA client thread. The initialization test requires an actual `apartment-MTA` observation, and `TestContextReaderRejectsSTABeforeAuthorization` forces STA and requires failure before READY or target authorization. The real owned-window test still requires visible text, password exclusion and the unchanged traversal deadline.

The actual reading invocation now emits six fixed stderr phase markers for GO receipt, reader entry, root acquisition, completed walking and flushed output. The private process owner also observes payload arrival, EOF and exit; errors contain only whitelisted phase names, parent-clock receipt times and exit status. It retains no raw stderr or field text. Observations freeze at the failure/deadline/cancel-watcher boundary before cleanup can create misleading EOF/exit events. The acceptance condition remains complete bounded stdout plus successful process exit. The 1.5-second post-GO bound still covers that whole operation; stage evidence is required before attributing a native stall to traversal or teardown.

`go test -race -count=1 ./infrastructure/windows` from `apps/desktop` executes the shared process protocol with actual owned subprocesses on macOS or Windows. Cases cover slow exit, complete output followed by nonzero exit, malformed/flood/private diagnostics, marker-like ordinary stdout, deadline/cancellation/authorization and child reaping. These portable checks do not execute UIA on macOS; actual MTA/provider/window checks remain Windows-only.

`TestOverlayInForeignFullscreenSpace` (DSK-A13, macOS) compiles and launches the owned AppKit editor fixture as a separate application, focuses Editor A and enters native fullscreen. Starting a production session in the isolated profile shows the actual failure overlay. The test checks `isOnActiveSpace` and the on-screen window-server list: the overlay overlaps and is ordered above the editor, while the editor's PID stays frontmost and its text view keeps focus. These observations catch windows whose `IsVisible()` is true in a different Space. Content PNG and compositor metadata are saved under `.workspace/e2e/darwin/`; no Screen Recording or Accessibility grant is needed for these checks. Cleanup exits the fixture's fullscreen Space and terminates only that owned process.

`TestCaptureReadsWebSite` (SCN-A04, macOS) is opt-in: with `ARION_E2E_SITE=1` and Accessibility granted to the process running the tests, it serves a local page with an autofocused text area, opens it in Safari and, when installed, Chrome, and requires the production target adapter to report a text field on host `127.0.0.1`, and no host once scene selection is off. Without the grant it fails rather than skipping. The browser windows it opens stay open.

`TestReadContextFromWindow` (CTX-A04, macOS) is opt-in the same way: with `ARION_E2E_CONTEXT=1`, and Accessibility and Screen Recording granted to the process running the tests, it opens a local page in Safari whose text area has text before the cursor, and requires `ReadContext` to return that text and the window's recognized heading, and nothing with its gates closed. Capture and recognition times are logged.

`TestLearnFromEditInOwnedEditor` (MEM-A09/A11, macOS) is opt-in with `ARION_E2E_LEARNING=1` and Accessibility granted to the test runner. In the owned AppKit editor fixture it inserts through the production target adapter, keeps following the field, has the fixture retype `jason` as `Jayson` through the text system, and requires the edit tracker to learn exactly that pair and release the field; a secure field must not be followed. The fixture's `replace` command exists for this test.

## Guarded macOS system paste

Run `make e2e-paste` or `pnpm e2e:paste` in an interactive macOS session with existing Accessibility access for the test process. Missing access fails explicitly; the test never grants permissions or changes input sources. Chrome coverage is skipped explicitly only if Chrome is absent.

`TestGuardedSystemPaste` exercises the production target capture/commit adapter, real Command-V dispatch, and observed text/input counts in a separate owned AppKit/WebKit fixture. It checks exact CJK/emoji/combining-mark/multiline selection replacement, duplicate rejection, insertion after a focus change and after a caret move, cancellation, stale session identity, secure fields and clipboard restoration. An installed Chrome is launched with a temporary isolated profile against a local page; both textarea and contenteditable must receive exactly one input event with the expected text. Only the owned Chrome instance and fixture are terminated. Original clipboard items are saved and restored only while the fixture still owns the test value; newer user clipboard data is preserved. The fixture has a standard Edit/Paste menu so Command-V follows actual AppKit key-equivalent dispatch.

Separate race-enabled adapter/coordinator tests inject pre/post-stage cancellation, post-send cancellation, blocked queue cancellation, competing transactions, unavailable clipboard and restore failure. Native transaction tests use real named pasteboards with multiple items/binary types and intercepted CGEvent delivery to check clipboard races, empty-board restoration and last-moment focus/range/secure refusal. These injected cases are not host E2E evidence. IMK composition regressions remain separate below. The paste E2E directly commits synthetic text and does not exercise microphone/recognition, actual Lark/Codex editors, office/terminal paste behavior or Windows.

## Windows Emoji candidates

`pnpm keyboard:windows:check` runs the production font-coverage probe and candidate renderer in an owned native window. It requires the installed Segoe UI Emoji font, verifies a smile's colored interior pixels against a neutral background, rejects missing/multiple-glyph sequences, and captures light/dark candidate rows at small/medium/large sizes. Evidence is written inside the `windows-tsf-keyboard` run directory. The fixture never changes installed fonts, registration or the user's input source.

The validated DLL tests read actual typed candidate metadata and confirm caret suppression/restoration and exact engine commits. The real ACP editor tests number/Space/punctuation selection, Chinese-prefix-plus-Emoji commits, unchanged Chinese-context ciphertext, live preference refresh, cancellation and stale hidden clicks. These use real TSF edit locks with manually dispatched COM key callbacks. They do not establish installed system-key dispatch, minimum/current Windows font coverage, browser/rich-text editor behavior or macOS installed-source acceptance. Run those editor scenarios separately before claiming them.
