入力メソッドにマイクとアクセシビリティの権限を渡すとき、OS が表示する確認ダイアログはどのアプリでも同じに見えます。しかしその裏側では、音声入力ツールは大きく2つに分かれます。マイクの音声をリモートサーバーにストリーミングして書き起こすものと、モデルを自分のコンピューター上で動かすものです。

音声入力はマイクを開き、カーソルがある入力欄にもアクセスするため、どんな機能よりも先に1つの問いが残ります。ショートカットキーを押して話している数秒のあいだに、録音された音声と変換されたテキストはどこへ行くのか。

Arion では、どちらもあなたのコンピューターに残ります。デバイス上でのライフサイクルと、それを自分で検証する方法を順に見ていきます。

## 1回の音声入力のデバイス上でのライフサイクル

<kbd>⌥</kbd> <kbd>Space</kbd> を押したとき、音声の取り込み、音声認識、オプションの整文はすべてローカルプロセス内で完結します。生の音声（PCM）は進行中の音声入力のあいだだけプロセスメモリに記録され、テキストが入力されるか途中でキャンセルされた時点でバッファは破棄されます。ディスク上に一時的な音声ファイルは残りません（受け入れ条件 `PRV-A03`）。認識の下書きとローカル整文もセッションメモリにとどまり、診断ログには書き込まれません。ウィンドウのコンテキストを有効にした場合も、スクリーンショットではなく OS のアクセシビリティ API を通じてフォーカス中の要素から限られた範囲のテキストだけを読み取り、パスワード欄や拒否リストに入れたアプリでは読み取りと学習をスキップします（`PRV-A05`）。

<embed-frame src="/blog/where-your-dictation-goes/shortcut.html" title="ショートカットを試す" ratio="16/7" caption="フレーム内で ⌥ Space を押すかクリックすると、模擬の音声入力が始まり、もう一度で終わります。何も録音されません。"></embed-frame>

セッションをまたいで保持する必要があるデータ（登録した語彙や、誤変換を修正したときに Arion が学習した単語ペア）は、ディスクに書き込む前に AES-256-GCM で暗号化されます。

<dictation-pill state="learned" term="Arion" label="Arion という単語を学習したことを示す音声入力ピルと、取り消しボタン" caption="修正後のピル。学習した単語はデバイス上に暗号化して保存されます。"></dictation-pill>

暗号鍵はデバイス上で生成され、macOS ではログインキーチェーンに、Windows では DPAPI で保護されて保管されます。鍵が見つからない場合や整合性チェックに失敗した場合はそのままエラーとし、平文での保存にフォールバックすることはありません。[^keys]

ローカルの診断エクスポート（`Settings › About`）も同じ境界を守ります。記録されるのはランダムな相関 ID、モデル識別子、処理時間の数値、エラーコードだけです。自動テスト（`PRV-A02`、`PRV-A10`）では、テスト実行中に模擬の認識テキスト、プロンプト、ファイルパス、トークンをカナリアとして注入し、ログやエクスポートされたアーカイブに1バイトでも含まれていればビルドを失敗させます。

## ネットワークを使う3つの場面

モデルのダウンロードが終われば、日常の音声入力とピンイン入力はネットワーク通信を一切発生させません（`PRV-A01`）。アプリ全体でネットワークを使うのは次の3つだけで、いずれも音声は送りません。

| リクエスト | 送るもの | タイミング |
| --- | --- | --- |
| モデルのダウンロード | 公開されたモデルファイルの取得要求。各ファイルは固定の SHA-256 ダイジェストで検証 | 初回利用前に一度 |
| アップデートの確認 | 選択したチャンネル（`stable` または `beta`）のみ。テキスト、語彙、デバイス識別子は含まず、アーカイブは Ed25519 署名で検証 | 自動（オフにできます） |
| サインインとクラウド整文 | 認識したテキストと有効にしたコンテキスト。音声は送らない | サインインまたはプロバイダー接続時のみ |

Arion にはクラウド音声認識もテレメトリーもありません。

<aside>

**同期はまだ利用できません。** 暗号化の境界は仕様で定まっています。各レコードはアップロード前にデバイス上で暗号化され、リレーサーバーから見えるのは暗号文のサイズとルーティング用のメタデータだけで、復号できるのは鍵を持つあなたのデバイスだけです（`PRV-A04`）。

</aside>

## 自分で確かめる

オープンソースのローカルツールの利点は、記事の説明をそのまま信じる必要がないことです。Arion は AGPL-3.0 で公開されており、新しいクローンから自分でビルドできます。

```sh
git clone https://github.com/AstraFoundry/Arion.git
cd Arion
make install
make build desktop
```

初回にモデルをダウンロードしたあと、Wi-Fi をオフにして（あるいはファイアウォールで外向き通信を遮断して）音声入力してみてください。ここに書いたことと異なる挙動があれば、それはバグです。[プライバシーのページ](/privacy/)と仕様[^spec]は、コードと同じ変更セットで更新されます。

[^keys]: 鍵がない場合や整合性チェックに失敗した場合はエラーになります（`PRV-A06`）。Arion が語彙を平文で保存したり、読めなくなった鍵を黙って作り直したりすることはありません。

[^spec]: リポジトリの[仕様 005：プライバシーと信頼境界](https://github.com/AstraFoundry/Arion/blob/main/specs/005-privacy.md)。
