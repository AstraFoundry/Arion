在电脑上给输入法授权麦克风和辅助功能时，操作系统弹出的权限提示看起来都差不多。但在这扇门背后，不同语音输入法走的是两条完全不同的路：大多数工具把你的麦克风音频流实时发到远端服务器转写；另一些则把模型跑在你的电脑上。

因为听写时麦克风开着、当前窗口的光标上下文也可读，一个具体的问题就绕不开：按住快捷键说话的那几秒里，录下的音频和转出的文字究竟去了哪里？

在 Arion 里，音频和转出的文字都留在你的电脑上。下面是它们在设备上的生命周期，以及你可以怎样自己验证。

## 一次听写在设备上的生命周期

按下 <kbd>⌥</kbd> <kbd>Space</kbd> 时，音频采集、语音识别和可选的文本润色都在本地进程内完成。原始音频（PCM）直接录进进程内存，只为正在进行的这次听写保留；松开按键完成上屏（或中途按取消）后，这块内存随即释放，不会在磁盘上留下临时录音文件（验收条件 `PRV-A03`）。识别草稿与可选的本地润色同样在会话内存里流转，不写入诊断日志。如果开启了窗口上下文，Arion 只通过系统辅助功能 API 读取当前焦点控件附近的有限文本，不截屏，遇到密码框或列入拒绝名单的应用时自动跳过读取与学习（`PRV-A05`）。

少数需要跨会话保留的数据（比如你手动添加的词表，或者更正错字后让 Arion 记住的词对）在写入本地存储前会先用 AES-256-GCM 加密：

<dictation-pill state="learned" term="Arion" label="Arion 的听写胶囊提示已学会 Arion 这个词，并带有撤销按钮" caption="更正之后的胶囊。学会的词加密保存在设备上。"></dictation-pill>

加密密钥在本机生成，macOS 上保存在系统的登录钥匙串（Keychain）中，Windows 上由 DPAPI 保护。如果密钥缺失或完整性校验失败，程序会直接报错，不会退回到明文存储。[^keys]

本地诊断日志（`Settings › About` 中的导出包）也遵守同样的边界：只记录随机关联 ID、模型代号、耗时数字和错误码。自动化验收测试（`PRV-A02`、`PRV-A10`）会在测试运行里故意注入模拟的敏感转写文本、提示词、路径和令牌，一旦在日志或导出压缩包里扫出任何一个字节，测试直接失败。

## 仅有的三类网络请求

模型下载完成后，日常听写和拼音打字不需要联网（`PRV-A01`）。整个应用只有三处地方会发起网络请求，且都不发送你的语音：

| 请求 | 发送什么 | 何时发生 |
| --- | --- | --- |
| 下载模型 | 请求公开的模型文件，每个文件下载后按固定的 SHA-256 摘要校验 | 首次使用前下载一次 |
| 检查更新 | 仅查询所选通道（`stable` 或 `beta`）的平台清单，不含文本、词表或设备标识，更新包经 Ed25519 签名校验 | 自动检查开启时，可在设置中关闭 |
| 登录与云端润色 | 识别后的文字与已启用的上下文，从不发送音频 | 仅在你主动登录或连接云端服务商时 |

除此之外，Arion 没有云端语音识别，也没有遥测上报。

<aside>

**多设备同步尚未推出。** 它的加密边界已写入规范：每条词表记录在上传前先在本机完成端到端加密，中继服务只能看到密文大小与路由元数据，只有持有密钥的你的设备能解密（`PRV-A04`）。

</aside>

## 自己验证

关于隐私的说明，最可靠的检验方式是不必相信文章的承诺。Arion 以 AGPL-3.0 协议开源，你可以直接从源码构建：

```sh
git clone https://github.com/AstraFoundry/Arion.git
cd Arion
make install
make build desktop
```

首次下载完本地模型后，关掉 Wi-Fi（或用防火墙阻断出站连接），再按住快捷键听写。如果这里写的任何一条与实际行为不符，那就是 bug；我们的[隐私页面](/privacy/)和隐私规范[^spec]都会与代码在同一次提交中一起更新。

[^keys]: 密钥缺失或完整性校验失败都会报错（`PRV-A06`）。Arion 绝不会退回到明文保存词汇，也不会自动生成新密钥覆盖旧的加密记录。

[^spec]: 仓库中的[规范 005：隐私与信任边界](https://github.com/AstraFoundry/Arion/blob/main/specs/005-privacy.md)。
