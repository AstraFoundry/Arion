# Shared keyboard core

## Learning and ranking

`learning.cpp` owns the in-memory records, binary-plist codec, transaction visibility, snapshot limits, validation, encrypted backup/restore and reset rules. `learning_rime.cpp` implements the pinned Rime private `Db`, `Transactional`, cursor and registry interfaces once for both platforms. Register the provider before Rime initialization; no stock plaintext database or text export is selected after any error.

Providers supply only OS cryptography, locking and atomic file primitives. macOS `../macos/learning.mm` retains Data Protection Keychain provisioning and policy checks and the original CryptoKit AES-256-GCM format (`ARIONUD1`, the existing database-name associated data, binary-plist arrays of NSData key/value pairs). Windows `learning_windows.cpp` uses current-user DPAPI with UI forbidden, database-name entropy and `ARIONWD1`; no key file or machine-wide protection flag is used. Windows snapshots are user/device-bound rather than an interchange format. Authentication and persistence failures do not replace the previous file. A failed writer rejects subsequent writes until explicit recovery. Reset refuses an active database and never rotates a system key.

macOS keeps its single-IMK-process exclusive database lease. Windows editors each load a TSF process, so their database leases are shared: the vault lease prevents reset, a second lock byte prevents deleting a live database, and a separate snapshot byte serializes only bounded reads/commits. A killed process releases both leases automatically. Each commit reloads the latest authenticated snapshot and reconciles the writer's observed base with its private pending changes before atomically replacing ciphertext. Reads refresh when the file identity/write-time revision changes; readonly editors do not block writers for their lifetime. Pending changes remain invisible and abortable. Unknown concurrent same-key replacement is an explicit conflict, never a guessed merge.

The Rime reconciler follows pinned 1.17 `src/rime/dict/user_dictionary.cc` (`UpdateEntry`, `UpdateTickCount`, `NewTransaction`), `src/rime/dict/user_db.cc` (`UserDbValue::Pack/Unpack`) and the SDK's actual `rime/algo/dynamics.h`. It replays the observed confirmation delta onto the latest `c=… d=… t=…` entry, remaps the writer's local clock advance onto the global committed clock and calls Rime's own `formula_d`. It does not hold a write lock throughout Rime's recent-confirmation undo window. The context reconciler uses the same transaction/clock mechanism for pair counts; stale eviction cannot erase a peer's newer confirmation. Both keep the original persisted record formats.

`ranking.cpp` owns context extraction, count/age scoring, stable producer-order ties, full-input-length filtering, confirmation updates and bounded eviction. `ranking_bridge.h` exposes the same implementation to Objective-C and C. `ranking_unicode.cpp` implements Unicode 17 extended grapheme boundaries from pinned official property tables, passing the complete official conformance corpus. Trailing punctuation/space/symbol trimming intentionally keeps the original macOS BMP-character policy, preserving existing context keys for supplementary symbols. No host text is read by the ranker.

Build the four shared C++17 objects `learning.cpp`, `learning_rime.cpp`, `ranking.cpp`, `ranking_unicode.cpp`; macOS adds its existing Objective-C++ provider and Swift CryptoKit object, Windows adds `learning_windows.cpp` and links `crypt32`, `advapi32`, `ole32`. Windows uses `RIME_IMPORTS` and the exact source-built Rime SDK/import library. Rime and the private adapter must be upgraded together.

`learning_test.cpp` exercises the common codec against an independently encoded legacy-format fixture and, on Windows, real DPAPI round trips, ciphertext canaries, nonce freshness, transaction visibility/abort, readonly/concurrent locks, dictionary binding, tamper rejection, backup/restore, active reset refusal and injected persistence failure. `learning_rime_test.cpp` checks the actual pinned runtime's private database/cursor/transaction/context ABI against the production provider. `learning_multiprocess_test.cpp` launches only owned, automatically reaped child processes: it verifies same/different-word merges, private pending/abort semantics, kills before commit and while holding the snapshot write lock, readonly refresh, independently paced real Rime sessions, exact total counts/global clock/dynamic weights, context ranking and active reset refusal. `ranking_test.cpp` runs the official 766-case Unicode corpus plus existing scoring, context, prefix-filter and eviction regressions. Fixture bytes, hashes and reproduction notes are in [`benchmarks/corpora/ime-learning-v1`](../../../../benchmarks/corpora/ime-learning-v1/README.md). The existing macOS native learning and typing tests remain required; portable tests do not establish macOS Keychain or AppKit behavior.
Both native adapters gate context confirmations with `rankingContainsHan`, using
the pinned Unicode 17 `Scripts.txt` property `Script=Han`. The C bridge
`arion_ranker_contains_han` accepts an explicit byte length and returns 1 for
Han, 0 for no Han, and -1 for malformed UTF-8 or a null pointer. It validates
the entire string, so a Han prefix cannot hide an invalid suffix. macOS no
longer depends on the OS regex Unicode version. Windows checks encrypted
runtime readiness first, then accepts a non-Han commit without writing context
learning. General `ContextRanker::learn` and `contextOf` retain their existing
unrestricted semantics. The generated property flags use 16 bits; the existing
grapheme and trailing-character masks remain unchanged.

## Engine and candidates

`pinyin.c` owns the Rime C API session/candidate operations and copied immutable snapshots, with strict Unicode boundary validation. `input.c` owns shortcut policy, Shift tap transitions and direct umlaut-to-v spelling normalization in Chinese mode; English and modified host events keep their original key values. `menu.c` owns the ranked leading window, lazy candidate loading, configurable pages, expanded rows and engine-index mapping. Native adapters retain editor composition, window rendering and platform key translation. A displayed candidate is never inserted directly; selection goes back through the actual Rime session.

Menu rebuilds reset candidate pages and highlights while preserving expansion during the current composition, including partial choices and suffix edits. Explicit collapse changes that retained state. The native owner disposes the menu when composition ends, so the next composition starts collapsed.

## Emoji candidates

`emoji.cpp` registers the `arion_emoji` Rime filter and exposes typed candidate metadata (`emoji.h`) to both hosts; the host may restrict sequences to what its system font can shape through `arion_emoji_set_support`. The offline index `emoji_data.h` is generated by `emoji_generate.py` from the pinned CLDR Simplified Chinese annotations and Unicode Emoji sequences recorded in `emoji_sources.json`, with the reviewed overrides in `emoji_aliases.json`; the source files are under `scripts/data/emoji`. `scripts/check-emoji-data.mjs` verifies, without a network or Python, the pinned source digests, the alias file, the checked-in header digest and the reviewed triggers against the fully-qualified Emoji set; the Windows keyboard checks and `pnpm keyboard:check` run it, and `pnpm keyboard:check` also runs `emoji_generate.py --check`, which regenerates the header and compares it. Emoji candidates keep their own type and engine index and are ignored by context ranking and learning ([KBD-08](../../../../specs/007-ime-ranking.md)).
