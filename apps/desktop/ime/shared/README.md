# Shared keyboard core

## Learning and ranking

`learning.cpp` owns the in-memory records, binary-plist codec, transaction visibility, snapshot limits, validation, encrypted backup/restore and reset rules. `learning_rime.cpp` implements the pinned Rime private `Db`, `Transactional`, cursor and registry interfaces once for both platforms. Register the provider before Rime initialization; no stock plaintext database or text export is selected after any error.

Providers supply only OS cryptography, locking and atomic file primitives. macOS `../macos/learning.mm` retains Data Protection Keychain provisioning and policy checks and the original CryptoKit AES-256-GCM format (`ARIONUD1`, the existing database-name associated data, binary-plist arrays of NSData key/value pairs). Windows `learning_windows.cpp` uses current-user DPAPI with UI forbidden, database-name entropy and `ARIONWD1`; no key file or machine-wide protection flag is used. Windows snapshots are user/device-bound rather than an interchange format. Authentication and persistence failures do not replace the previous file. A failed writer rejects subsequent writes until explicit recovery. Reset refuses an active database and never rotates a system key.

macOS keeps its single-IMK-process exclusive database lease. Windows editors each load a TSF process, so their database leases are shared: the vault lease prevents reset, a second lock byte prevents deleting a live database, and a separate snapshot byte serializes only bounded reads/commits. A killed process releases both leases automatically. Each commit reloads the latest authenticated snapshot and reconciles the writer's observed base with its private pending changes before atomically replacing ciphertext. Reads refresh when the file identity/write-time revision changes; readonly editors do not block writers for their lifetime. Pending changes remain invisible and abortable. Unknown concurrent same-key replacement is an explicit conflict, never a guessed merge.

The Rime reconciler follows pinned 1.17 `src/rime/dict/user_dictionary.cc` (`UpdateEntry`, `UpdateTickCount`, `NewTransaction`), `src/rime/dict/user_db.cc` (`UserDbValue::Pack/Unpack`) and the SDK's actual `rime/algo/dynamics.h`. It replays the observed confirmation delta onto the latest `c=… d=… t=…` entry, remaps the writer's local clock advance onto the global committed clock and calls Rime's own `formula_d`. It does not hold a write lock throughout Rime's recent-confirmation undo window. The context reconciler uses the same transaction/clock mechanism for pair counts; stale eviction cannot erase a peer's newer confirmation. Both keep the original persisted record formats.

`ranking.cpp` owns context extraction, count/age scoring, stable producer-order ties, full-input-length filtering, non-Han candidate slot preservation, confirmation updates and bounded eviction. `ranking_bridge.h` exposes the same implementation to Objective-C and C. `ranking_unicode.cpp` implements Unicode 17 extended grapheme boundaries from pinned official property tables, passing the complete official conformance corpus. Trailing punctuation/space/symbol trimming intentionally keeps the original macOS BMP-character policy, preserving existing context keys for supplementary symbols. No host text is read by the ranker.

Build the shared C++17 learning/ranking objects, `emoji.cpp`, `english.cpp` and `english_lexicon.cpp`; macOS adds its existing Objective-C++ provider and Swift CryptoKit object, Windows adds `learning_windows.cpp` and links `crypt32`, `advapi32`, `ole32`. Windows uses `RIME_IMPORTS` and the exact source-built Rime SDK/import library. Rime and the private adapter must be upgraded together.

`learning_test.cpp` exercises the common codec against an independently encoded legacy-format fixture and, on Windows, real DPAPI round trips, ciphertext canaries, nonce freshness, transaction visibility/abort, readonly/concurrent locks, dictionary binding, tamper rejection, backup/restore, active reset refusal and injected persistence failure. `learning_rime_test.cpp` checks the actual pinned runtime's private database/cursor/transaction/context ABI against the production provider. `learning_multiprocess_test.cpp` registers the same bilingual translator and Emoji component required by the packaged schema before creating worker sessions. It launches only owned, automatically reaped child processes: it verifies same/different-word merges, private pending/abort semantics, kills before commit and while holding the snapshot write lock, readonly refresh, independently paced real Rime sessions, exact total counts/global clock/dynamic weights, context ranking and active reset refusal. `ranking_test.cpp` runs the official 766-case Unicode corpus plus existing scoring, context, prefix-filter and eviction regressions. Fixture bytes, hashes and reproduction notes are in [`benchmarks/corpora/ime-learning-v1`](../../../../benchmarks/corpora/ime-learning-v1/README.md). The existing macOS native learning and typing tests remain required; portable tests do not establish macOS Keychain or AppKit behavior.
Both native adapters gate context confirmations with `rankingContainsHan`, using
the pinned Unicode 17 `Scripts.txt` property `Script=Han`. The C bridge
`arion_ranker_contains_han` accepts an explicit byte length and returns 1 for
Han, 0 for no Han, and -1 for malformed UTF-8 or a null pointer. It validates
the entire string, so a Han prefix cannot hide an invalid suffix. macOS no
longer depends on the OS regex Unicode version. Windows checks encrypted
runtime readiness first, then accepts a non-Han commit without writing context
learning. General `ContextRanker::learn` and `contextOf` retain their existing
unrestricted semantics. The generated property flags use 16 bits; the existing
grapheme and trailing-character masks remain unchanged.

## Engine and candidates

`pinyin.c` owns the Rime C API session/candidate operations and copied immutable snapshots, with strict Unicode boundary validation. `input.c` owns shortcut policy, Shift tap transitions and direct umlaut-to-v spelling normalization in Chinese mode; English and modified host events keep their original key values. `menu.c` owns the ranked leading window, lazy candidate loading, configurable pages, expanded rows and engine-index mapping. Native adapters retain editor composition, window rendering and platform key translation. A displayed candidate is never inserted directly; selection goes back through the actual Rime session.

Menu rebuilds reset candidate pages and highlights while preserving expansion during the current composition, including partial choices and suffix edits. Explicit collapse changes that retained state. The native owner disposes the menu when composition ends, so the next composition starts collapsed.

`english.cpp` registers one `arion_bilingual` translator after initialization and before sessions. It delegates Chinese to the original encrypted script translator and uses grouped English data with disjoint exact/suggestion/lookup cursors. Rime's packaged Prism/Syllabifier identifies full normal Pinyin; familiar exact words and evidence-qualified completions replace the fixed English preview. Original candidate objects and only scalar segment bounds are retained, avoiding a Segment/menu/translation ownership cycle. The [data policy](keyboard-data/README.md) describes ordering, exhaustive paging, source counts and conservative limits. Both hosts propagate loader failures; Windows reset and multiprocess engine fixtures restore all custom components.

Standalone Shift from Chinese to English first calls `arion_pinyin_commit_raw` for pending input. This uses the schema's raw Return action with full-width formatting disabled during the commit. The native host delivers the engine result once through its owned range before switching to English pass-through. Confirmed Chinese segments survive, while pending letters retain their raw spelling without preedit spacing or candidate completion. Shift+Space and menu switching retain their discard policy.

## Case, mixed ranges and approved vocabulary

The bilingual producer retains the original whole-input English lanes and data. Explicit uppercase/title/mixed-case input transforms source display only over the consumed English span. Exact proper-prefix membership uses the same sorted keys, bounded by the existing 128-byte word limit; it does not scan completions or constrain total mixed-input length. Unmatched normal Pinyin keeps its existing Chinese page. Other unmatched input can offer finite shorter English candidates after full-range Chinese proposals. Only scalar bounds/raw spelling are retained, so translations cannot retain a Segment/menu cycle.

`spelling.cpp` provides the Chinese child, opt-in four-kind typo correction, eleven independent fuzzy pairs and explicitly read personal terms. `personal_vocabulary_store.cpp` persists a separately encrypted projection of approved application records. Both hosts register spelling before bilingual session creation, preserve raw Shift behavior and expose metadata with actual consumed start/end. Shared menu/ranking contracts keep English slots fixed and do not promote candidates covering a different raw span. Personal and English non-Phrase candidates cannot silently become ordinary learned dictionary words.
