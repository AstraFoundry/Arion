# Arion Pinyin profile

`arion_pinyin.schema.yaml` explicitly adapts the pinned Apache-2.0 `pinyin_simp` schema. It retains that dictionary's full-Pinyin spelling rules, abbreviation, punctuation, native candidate selection and editing. The inherited `express_editor` makes Space choose a candidate, Enter commit raw input and Escape clear composition. Brackets and minus/equal page through nine candidates. Ordinary symbols use direct commit mappings instead of the inherited symbol lists, with paired Chinese quotes. The inherited `full_shape` and `ascii_punct` switches back the input menu's width and punctuation items: `ascii_punct` bypasses the table so ASCII punctuation passes through, and full width reuses the same table while Rime's built-in shape formatter widens ASCII output. Slash-code symbol recognition, stroke reverse lookup and alternate schemas are excluded from this profile.

The dictionary retains its AOSP PinyinIME provenance header. Prelude defaults/symbols are separately licensed LGPL-3.0 configuration assets. `scripts/keyboard-runtime.json` records immutable upstream URLs, exact bytes and licenses. The staging script ships those license and source references beside the compiled data.

`translator/db_class` requires Arion's encrypted user database. Never replace it with Rime's plaintext `userdb`. The runtime opens prebuilt data and must not deploy schemas or run Rime user-data synchronization. The immutable schema closure is compiled during staging, with no personal learning data. Build-only public/private headers and Boost dependencies stay in `.workspace/keyboard-runtime/sdk`.

The `arion_emoji` filter is implemented in the shared native host source, not supplied by rime-emoji. `emoji_data.h` is generated by `emoji_generate.py` from the checked-in, digest-pinned CLDR 48.2 Simplified Chinese annotations and Unicode Emoji 15.0 fully-qualified sequences. The 30 entries in `emoji_aliases.json` override ambiguous common words. Regenerate with `python3 apps/desktop/ime/shared/emoji_generate.py` and verify with its `--check` option or `node scripts/check-emoji-data.mjs`. The generated index holds Unicode text rendered by the operating system, with no Emoji artwork. The Unicode license and `emoji_sources.json` provenance travel with the native runtime. macOS enables the filter per session from the `emojiSuggestions` keyboard preference. Windows registers the component for the shared schema but currently leaves the option off until native acceptance.

## English words in Chinese mode

The shared `arion_bilingual` translator wraps the shared Chinese spelling/personal translator and a complete immutable English lexicon. It replaces the old English Rime schema/table and permanent prefix aliases. Both hosts use identical sources, candidate identities and data; no network, deployment or model inference runs while typing.

ESDB level 70, A/B/Z variant 1 supplies general membership. Original CSpell software/company files supply technical spellings. Standalone ASCII letters of length 2–128 retain native display case and lowercase lookup; compound syntax, punctuation, apostrophes and phrases are not silently flattened. There are 150,615 keys and 284,705 display forms including derived sentence case. Membership remains independent of frequency.

`scripts/lib/keyboard-english.mjs` emits TSV v2 with one row per key: lowercase key, unique word rank, pinned observed count (zero means unobserved), and ordered comma-separated display forms. CSpell native case and genuine ESDB variants survive; sentence case is derived only under the existing ordinary-lowercase rule. Word ordering uses FrequencyWords count, key length and ASCII ties; technical-source membership is not an automatic word boost. The loader rejects old formats, invalid fields, duplicate keys/ranks/displays and incomplete families.

`english_lexicon.cpp` owns disjoint exact, suggestion and lookup cursors. A key belongs to one minimum-prefix bucket and rank tournament, avoiding replay/dedup or a full-prefix predicate scan. Automatic mixed-mode completion requires at least five input letters, an observed count of at least 1,000 and at least half the completed spelling. These are explicit Arion policy settings, not calibrated language probabilities. Unknown/low counts retain exact and exhaustive lookup. Each cursor holds the immutable lexicon and independent query-local heaps.

`english.cpp` uses the packaged Pinyin Prism and Rime's exported Syllabifier to identify complete normal Pinyin independently of the leading candidate's provenance. Complete Pinyin protects the first Chinese result, including sentences and personal entries, and up to three full-range Chinese candidates before one familiar exact English form. Familiarity requires native lowercase spelling and the observed-count floor above; case-folded equality alone does not promote rare/proper-name homographs.

Outside complete Pinyin, an exact English word can lead only at the same input-length threshold used for automatic completion, with the caret and segment at the end of the composition. Short exact matches and admitted completions follow the first Chinese candidate. Only one exact/suggestion display form is automatically advanced. Chinese then fills the rest of the largest supported native first page (`ARION_MENU_MAX_PAGE_SIZE` in `menu.h`), keeping both five/nine-slot menus quiet. If Chinese exhausts early, the English tail naturally fills the available space. The deferred exact-case, suggestion and lookup cursors remain exhaustive; after that protected region, groups of two Chinese candidates and one English candidate keep both lazy tails reachable. This bounded tail scheduling adapts msime's finite-list policy to Rime's potentially large lazy stream. No Chinese/English dictionary scores are compared.

`hel` keeps Chinese first and no longer automatically completes to `hello`; its exact `Hel` and deferred lookup remain selectable. `artifi` can show `artificial` after the Chinese first choice. A full non-Pinyin English spelling such as `hello` can lead. Exact variants such as `Hello` remain available through paging rather than consuming another automatic slot. Normal Pinyin such as `xin` retains its Chinese first page. Approved partial English choices retain their previous whole-Chinese-before-prefix scheduling, original consumed ranges and engine-owned suffix conversion. Rare technical prefixes can require more typing or paging.

Original Chinese Phrase objects and English non-Phrase candidates retain real engine selection, revision ownership and Chinese-only encrypted learning. Neither this change nor source counts introduce English personal learning or editor-context collection. Missing Prism or malformed lexicon fails initialization explicitly before session creation. The industrial evidence and policy limits are in the repository's English candidate admission research document.

The pinned source bytes and complete notices ship under `licenses/esdb`, `licenses/cspell` and `licenses/frequencywords`. FrequencyWords attribution/CC BY-SA 4.0 terms remain; the derived ranked data retains those terms and complete ESDB/CSpell notices. `node scripts/import-keyboard-english.mjs` reproduces the ESDB export; Python/SQLite are source-maintenance dependencies only. Normal generation uses portable Node. Pure index tests, native five/nine-slot authored cases, package verification and installed-editor acceptance are separate gates.

## Spelling and mixed input

The profile admits uppercase ASCII into owned composition and disables the inherited uppercase recognizer bypass. The bilingual translator folds English lookup, preserves source case for lowercase input and follows explicit typed case over each English span. Its original admission/ordering thresholds and generated lexicon bytes are unchanged. Exact-word prefix choices use the same lexicon only when the whole input has no English match and is not normal full Pinyin; shorter ranges let the existing engine convert the remaining suffix.

Correction is enabled at the engine capability boundary, while the shared corrector checks per-session typo/fuzzy options that default off. Do not globally increase sentence or homophone counts: unchanged normal Chinese pages are a regression gate. Both packages require the reviewed correction-identity Rime source patch and exported native interfaces. Approved personal terms require explicit dictionary-resolvable readings and encrypted, revisioned projection delivery; they are independent of engine learning and the generated English data.
