# Arion Pinyin profile

`arion_pinyin.schema.yaml` explicitly adapts the pinned Apache-2.0 `pinyin_simp` schema. It retains that dictionary's full-Pinyin spelling rules, abbreviation, punctuation, native candidate selection and editing. The inherited `express_editor` makes Space choose a candidate, Enter commit raw input and Escape clear composition. Brackets and minus/equal page through nine candidates. Ordinary symbols use direct commit mappings instead of the inherited symbol lists, with paired Chinese quotes. The inherited `full_shape` and `ascii_punct` switches back the input menu's width and punctuation items: `ascii_punct` bypasses the table so ASCII punctuation passes through, and full width reuses the same table while Rime's built-in shape formatter widens ASCII output. Slash-code symbol recognition, stroke reverse lookup and alternate schemas are excluded from this profile.

The dictionary retains its AOSP PinyinIME provenance header. Prelude defaults/symbols are separately licensed LGPL-3.0 configuration assets. `scripts/keyboard-runtime.json` records immutable upstream URLs, exact bytes and licenses. The staging script ships those license and source references beside the compiled data.

`translator/db_class` requires Arion's encrypted user database. Never replace it with Rime's plaintext `userdb`. The runtime opens prebuilt data and must not deploy schemas or run Rime user-data synchronization. The immutable schema closure is compiled during staging, with no personal learning data. Build-only public/private headers and Boost dependencies stay in `.workspace/keyboard-runtime/sdk`.

The `arion_emoji` filter is implemented in the shared native host source, not supplied by rime-emoji. `emoji_data.h` is generated by `emoji_generate.py` from the checked-in, digest-pinned CLDR 48.2 Simplified Chinese annotations and Unicode Emoji 15.0 fully-qualified sequences. The 30 entries in `emoji_aliases.json` override ambiguous common words. Regenerate with `python3 apps/desktop/ime/shared/emoji_generate.py` and verify with its `--check` option or `node scripts/check-emoji-data.mjs`. The generated index holds Unicode text rendered by the operating system, with no Emoji artwork. The Unicode license and `emoji_sources.json` provenance travel with the native runtime. macOS enables the filter per session from the `emojiSuggestions` keyboard preference. Windows registers the component for the shared schema but currently leaves the option off until native acceptance.

## English words in Chinese mode

The shared Pinyin profile mounts `table_translator@english`, using the build-only `arion_english.schema.yaml` dependency. `scripts/lib/keyboard-english.mjs` derives its 38,010 ASCII words of at least two letters from SCOWL 2020.12.07 tiers 10/20/35, decoded as ISO-8859-1. The original lists and complete notice ship under `licenses/scowl`.

The generator builds prefix aliases from three letters. For each prefix it retains up to three distinct words, ordered by the pinned Hermit Dave FrequencyWords OpenSubtitles 2018 counts, then SCOWL coverage tier, word length and ASCII order. An exact word always leads its own code, even if it was outside that prefix's top three. Missing frequency counts mean zero observed occurrences in this source, not an estimated frequency. The subtitle source favors conversational vocabulary and does not establish technical-domain or competitor parity.

Each code has at most four candidates. Exact codes offer the lowercase word and its sentence-initial variant first, followed by up to two longer matches. Incomplete codes offer up to three lowercase completions followed by the leading word's sentence-initial variant. Two-letter codes offer exact words only. `artifi` therefore offers `artificial` before the full word is typed. Rime's runtime `enable_completion` remains false: the generated aliases already contain the complete bounded result, avoiding unbounded native predictive enumeration.

The bounded shared `arion_english` filter buffers at most four English entries and three whole-input Chinese dictionary words. Chinese words keep priority; generated Chinese sentences and shorter prefixes follow English. The context ranker leaves non-Han slots in place. The menu protects English's first-page slots from optional Emoji. English sentence construction and learning remain disabled. Uppercase events keep inherited ASCII handling; apostrophes remain Pinyin separators and Enter commits raw input.

The frequency source, upstream README and full CC BY-SA 4.0 notice are retained under `scripts/data/english/frequencywords` and shipped under `licenses/frequencywords`; the manifest pins original bytes and revisions. The modified generated prefix dictionary is distributed under CC BY-SA 4.0 with its SCOWL notices retained. Arion's generator and native logic are independently implemented; no WeChat binaries, proprietary data or third-party Lua implementations are bundled.

Both staging paths precompile the English table/prism/reverse data and validate its read-only policy. The runtime never generates a dictionary or deploys a schema while typing. Native engine/AppKit/TSF tests remain separate from installed-source editor acceptance.
