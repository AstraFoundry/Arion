# Arion Pinyin profile

`arion_pinyin.schema.yaml` explicitly adapts the pinned Apache-2.0 `pinyin_simp` schema. It retains that dictionary's full-Pinyin spelling rules, abbreviation, punctuation, native candidate selection and editing. The inherited `express_editor` makes Space choose a candidate, Enter commit raw input and Escape clear composition. Brackets and minus/equal page through nine candidates. Ordinary symbols use direct commit mappings instead of the inherited symbol lists, with paired Chinese quotes. The inherited `full_shape` and `ascii_punct` switches back the input menu's width and punctuation items: `ascii_punct` bypasses the table so ASCII punctuation passes through, and full width reuses the same table while Rime's built-in shape formatter widens ASCII output. Slash-code symbol recognition, stroke reverse lookup and alternate schemas are excluded from this profile.

The dictionary retains its AOSP PinyinIME provenance header. Prelude defaults/symbols are separately licensed LGPL-3.0 configuration assets. `scripts/keyboard-runtime.json` records immutable upstream URLs, exact bytes and licenses. The staging script ships those license and source references beside the compiled data.

`translator/db_class` requires Arion's encrypted user database. Never replace it with Rime's plaintext `userdb`. The runtime opens prebuilt data and must not deploy schemas or run Rime user-data synchronization. The immutable schema closure is compiled during staging, with no personal learning data. Build-only public/private headers and Boost dependencies stay in `.workspace/keyboard-runtime/sdk`.

The `arion_emoji` filter is implemented in the shared native host source, not supplied by rime-emoji. `emoji_data.h` is generated by `emoji_generate.py` from the checked-in, digest-pinned CLDR 48.2 Simplified Chinese annotations and Unicode Emoji 15.0 fully-qualified sequences. The 30 entries in `emoji_aliases.json` override ambiguous common words. Regenerate with `python3 apps/desktop/ime/shared/emoji_generate.py` and verify with its `--check` option or `node scripts/check-emoji-data.mjs`. The generated index holds Unicode text rendered by the operating system, with no Emoji artwork. The Unicode license and `emoji_sources.json` provenance travel with the native runtime. macOS enables the filter per session from the `emojiSuggestions` keyboard preference. Windows registers the component for the shared schema but currently leaves the option off until native acceptance.

## English words in Chinese mode

The profile mounts one `arion_bilingual` translator. Its Chinese delegate is Rime's builtin script translator, created through the generic component interface with the existing encrypted `translator` configuration. Its independent English producer reads `arion_english.lexicon`, a strict versioned TSV generated by `scripts/lib/keyboard-english.mjs`. The old English schema, compiled Rime table and capped prefix aliases are removed.

The pinned ESDB export uses level 70, American/British/British-ize spellings (`A,B,Z`), variant level 1. Original CSpell software terms, coding terms, computing acronyms, software tools/services, networking, cybersecurity and company names supplement it. The importer accepts standalone ASCII alphabetic spellings of 2–128 letters; it retains source display case separately from lowercase lookup. Phrases, punctuation, apostrophes and CSpell compound syntax are outside this letter-input profile, rather than being silently flattened. These sources currently yield 150,615 lookup keys and 284,705 distinct display forms including derived sentence case.

An identical display is deduplicated. CSpell source spellings rank before other case variants of the same key; source-native ESDB variants remain available. Sentence case is derived from lowercase entries only when there is no CSpell non-lowercase spelling, preventing invented brand capitalization. Prefix completion shows each word's preferred spelling once; exact input exposes its remaining case variants. Membership is independent of frequency. Global word order uses pinned Hermit Dave FrequencyWords OpenSubtitles 2018 counts, technical-source membership, key length and ASCII ties. The ESDB export provides membership, not per-word coverage tiers, so ranking does not invent tier values.

The shared loader validates fields, counts, lexical order, rank permutation and bounded contiguous case families before building one immutable tournament tree. Cursors retain the shared lexicon and own their priority queues. Prefix interval binary searches and best-first traversal produce ranked matches incrementally; no per-key full-dictionary scan, permanent top-k cutoff or repeated prefix storage is used. Two-letter input is exact-only; completion starts at three letters. The tree is built once at runtime startup; schema deployment and network access never occur while typing.

Mixed translation yields up to three whole-input Chinese dictionary words, four English preview candidates, then two Chinese / one English tail candidates, skipping an exhausted source. Every later word remains pageable without burying the other language. Original Chinese Phrase identities and encrypted learning remain intact. English uses non-Phrase engine candidates, so normal engine selection commits the source text once without adding it to Chinese learning. Existing menu indices, stale-revision checks, raw Enter and ownership rules remain unchanged.

`scripts/keyboard-runtime.json` pins every original source/export byte and notice. ESDB's original Copyright and export documentation ship under `licenses/esdb`; original CSpell sources and both package MIT notices ship under `licenses/cspell`. The frequency source, attribution and complete CC BY-SA 4.0 license remain under `licenses/frequencywords`; the modified ranked lexicon is distributed under CC BY-SA 4.0 with all ESDB/CSpell notices retained. No competitor code, data or Lua implementation is bundled.

Run `node scripts/import-keyboard-english.mjs` to reproduce the reviewed ESDB export from its pinned source archive (Python 3 and SQLite are developer source-maintenance dependencies only). Normal staging and generation use portable dependency-free Node. `node scripts/test-english-lexicon.mjs` checks the real C++ query, all 1,024 synthetic shared-prefix matches, exact/case policy, independent/lifetime-safe cursors, first-result tree-work bounds and malformed input rejection. Native engine/AppKit/TSF and installed-editor checks remain separate gates.
